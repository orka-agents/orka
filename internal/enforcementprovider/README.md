# Enforcement providers

This package authenticates provider descriptors, preserves exact policy bytes, verifies signed activation/readback proof, and keeps a workload held until proof consumption and its release obligation are committed atomically. Providers implement prepare, activate, independent readback, proof, release, status, reconciliation, and cleanup. The signed protocol uses versioned length-framed transcripts and binds the complete authorization. Durable cleanup retains replay-safe tombstones. File-backed controllers bind state to one absolute path, reject hard-link aliases, have exclusive lifetime ownership, and must be closed. Policy contents remain provider-owned opaque bytes; Orka validates only generic bounds, digest, and capabilities.

> **Protocol revision:** this implementation negotiates `orka.enforcement-provider/v2` and Unix frame version `2`. Revision 2 intentionally replaces the draft v1 number/RFC3339 timestamp mix, proof transcript, authorization digest, and cleanup request contract. A v1-only descriptor or frame is rejected; it is never decoded under v2 semantics.

Persisted proof-bearing attempts are treated as untrusted during recovery. Before any provider status, release, or cleanup side effect, Orka reauthenticates the pinned descriptor and authorization, reverifies the proof signature and every binding, recomputes the proof digest, and recomputes any release and cleanup obligation IDs. A mismatch fails closed with zero provider calls. Provider response envelopes and every nested operation result use the same bounded, depth-limited decoder and reject duplicate keys, unknown fields, and trailing JSON.

`FileStore` requires its canonical parent directory to be private (`0700`) and owned by the current effective user. It holds the validated private parent directory lock for its lifetime. Its sidecar lock is opened without following symlinks, must be an owner-matching regular single-link file with private permissions, and is checked against the pathname inode after locking and again before operations. Lock replacement makes the live store fail closed.
