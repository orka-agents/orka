# Enforcement provider lifecycle

The `internal/enforcementprovider` package coordinates policy enforcement while a workload remains held. Orka does not select the provider implementation; operators pin its identity and trust material.

Operator configuration supplies a `TrustProfile` that pins provider ID, endpoint identity, Ed25519 key ID/key, minimum epoch, and algorithm. Orka verifies the descriptor signature and freshness against that profile before consuming the descriptor's proof key. A self-signed substitute, wrong endpoint, stale or revoked descriptor, unsupported protocol, or unsupported required capability fails closed.

Authorization treats provider policy bytes as opaque and binds their exact digest, generic capability list, request, attempt, workload, provider, audience, challenge, and idempotency key into the signed proof transcript. The provider performs prepare, activate, independent readback, and proof operations. The workload stays held after activation. First proof consumption rechecks freshness, every immutable authorization binding, the proof digest, and the signature in the same compare-and-swap that creates an immutable release obligation. Cleanup uses a durable idempotency identity and retains a `Cleaned` tombstone so provider resources can disappear without erasing replay protection. `FileStore` deep-copies mutable state, strictly validates its versioned JSON, binds each state file to its canonical absolute path, rejects hard-link aliases, holds path and inode locks for its lifetime, and requires `Close` before another controller can own the same path.

`NewUnixProvider` uses a bounded versioned JSON protocol over a Unix socket and authenticates the server UID with Linux peer credentials. Other platforms compile but fail closed at peer authentication; UID authentication identifies an OS principal, not a cryptographically unique process. The synthetic provider remains available for isolated tests. The external conformance test drives a configured server by supplying socket and trust-file environment variables.
