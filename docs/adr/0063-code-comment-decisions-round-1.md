# 63. Decisions recovered from code comments, round 1

Date: 2026-11-22

## Status

Accepted. This record is a catalog produced by the comment ban in
[ADR 0062](0062-code-carries-no-comments.md). Each entry was a code comment that recorded a
non-obvious decision. The comment was deleted, and the decision now lives here.

## Context

Round 1 classified 1338 comment groups across 32 packages. 563 of them
recorded decisions that a reader of the code alone could get wrong. Where an earlier ADR
already records a decision, the entry links that ADR instead of restating its reasoning.

## Decision

Each entry names the symbol it governs, so `rg '<symbol>'` finds the code. Entries
are grouped by package and ordered by source position as of round 1.

### `internal/agentcontext`

- **Resolved soul text is sensitive** (`agentcontext.ResolvedSoul`): agentcontext.ResolvedSoul.Text holds the exact persona bytes selected by an explicit Agent source and is treated as sensitive configuration: it must never be logged or exposed in Task status; only its Digest may be recorded.
- **Souls are never discovered from repositories** (`agentcontext.ResolveSoul`): agentcontext.ResolveSoul resolves a soul only from the Agent's inline text or a single ConfigMap object version pinned by an expected digest; it deliberately performs no repository discovery (for example a SOUL.md in the workspace), so repository content cannot inject a persona.
- **Soul composition is prompt guidance only** (`agentcontext.Compose`): agentcontext.Compose leaves the role prompt byte-identical when no soul is configured, and the persona heading/footer hierarchy it adds is prompt guidance only; it is not output validation or an authorization boundary, so no security property may depend on the model obeying it.
- **Session digest excludes per-Task fields** (`agentcontext.SessionDigest`): agentcontext.SessionDigest zeroes TaskGeneration and InputsDigest before hashing a TaskSoulBinding so different Tasks can continue the same Agent revision's Session, while any change to role, persona, or Agent identity forces a new Session.
- **Inputs digest records empty collections** (`agentcontext.TaskInputsDigest`): agentcontext.TaskInputsDigest hashes the Task's execution inputs (spec minus mutable control fields) and appends the JSON path of every present-but-empty slice or map, because JSON omits empty collections while an explicitly empty node selector, toleration list, or tool policy behaves differently from an omitted one.
- **Soul bindings survive control-field edits** (`agentcontext.SoulBindingMatches`): agentcontext.SoulBindingMatches uses TaskGeneration only to identify the first binding; once an inputs digest is recorded, the digest proves execution inputs are unchanged so control-field edits that bump the generation keep the binding. Bindings recorded without an inputs digest fall back to an exact generation match.
- **Soul digest covers source text only** (`agentcontext.Digest`): The soul digest recorded for an Agent (agentcontext.Digest over ResolvedSoul.Text) is computed over the source persona bytes, never over the rendered heading/footer envelope Compose produces, so envelope wording changes do not invalidate pinned digests.
- **Inline Copilot checks are not sufficient** (`agentcontext.ValidateInlineCopilotInstructions`): agentcontext.ValidateInlineCopilotInstructions validates only the inline system prompt and soul of a Copilot harness v2 Agent and never resolves ConfigMaps; the controller must still validate the fully resolved configuration before dispatch.
- **Agent writes mirror reconciler validation** (`agentcontext.ValidateAgentWrite`): agentcontext.ValidateAgentWrite runs every soul and instruction check that needs no ConfigMap resolution at API write time, so the API never persists an Agent its reconciler would immediately reject.
- **Empty placement differs from omitted** (`agentcontext.TaskInputsDigest`): An explicitly empty Task nodeSelector or tolerations list clears the Agent's placement, while an omitted one inherits it; agentcontext.TaskInputsDigest must therefore produce different digests for the two.

### `internal/aitools`

- **Gateway reply scope checks restrictions only** (`aitools.ACPGatewayReplyScopeAllows`): aitools.ACPGatewayReplyScopeAllows evaluates only Task restrictions (type, parentage, read-only), never origin or runtime authorization. Both the frozen policy projection and live sender admission call it, so it must stay free of authorization side inputs.
- **Gateway reply eligibility comes from durable origin resolution** (`aitools.ResolveWithGatewayReply`): aitools.ResolveWithGatewayReply grants reply_in_conversation only when the controller's durable event/TaskUID resolution marks the Task eligible; Task metadata never grants it. Plain Resolve strips gateway-only tools even when explicitly requested.
- **Explicit native tool policy beats durable origin grant** (`aitools.gatewayReplyPolicyAllows`): aitools.gatewayReplyPolicyAllows keeps an explicit native tool policy authoritative even when a durable gateway origin makes the Task eligible, so an explicit empty or restricted tool list cannot be widened by the grant.
- **Remote MCP Tasks cannot reference cross-namespace Agents** (`aitools.ValidateRemoteMCPAgentReference`): aitools.ValidateRemoteMCPAgentReference enforces the remote-only Task boundary before any consumer reads the Agent. It is separate from namespace isolation because the backend does not grant workers cross-namespace Agent access.
- **Remote MCP ceiling is enforced outside Resolve** (`aitools.ValidateRemoteMCPSelection`): aitools.ValidateRemoteMCPSelection enforces the native Agent's remote-only tool ceiling; aitools.Resolve intentionally keeps its additive behavior for other Tools, so consumers that load Tool CRs must call both.
- **Remote MCP contract is revalidated at consumers** (`aitools.ValidateRemoteMCPConfiguration`): aitools.ValidateRemoteMCPConfiguration reapplies the remote-only contract at every consumer because Tools can be written by clients that bypass Kubernetes admission; admission is not the trust boundary.
- **Remote MCP URLs never carry credentials in query** (`aitools.ValidateRemoteMCPConfiguration`): aitools.ValidateRemoteMCPConfiguration lets a remote MCP endpoint query select a route but rejects any query parameter whose name looks like a credential or signature.
- **Remote MCP URL credential denylist is URL-specific** (`aitools.remoteMCPURLCredentialName`): aitools.remoteMCPURLCredentialName extends the controller's signed-query denylist with access-ID separator variants and remote token checks; the extra names apply only to URLs so custom-header admission is unchanged.
- **Remote MCP schemas keep exact numbers and load nothing external** (`aitools.ResolveRemoteMCPParameters`): aitools.ResolveRemoteMCPParameters compiles the reviewed schema without loading external resources, and both schema bounds and instances keep exact JSON numbers because a binary64 representation would round reviewed bounds.
- **Remote MCP schemas keep exact numbers and load nothing external** (`aitools.ResolveRemoteMCPParameters`): aitools.ResolveRemoteMCPParameters also decodes a bounded google jsonschema representation solely for cardinality and local-reference checks (so refs into untyped Extra data cannot bypass bounds); its binary64 values are never used for instance validation.
- **Remote MCP numeric budget bounds rational expansion** (`aitools.ValidateRemoteMCPNumericBudget`): aitools.ValidateRemoteMCPNumericBudget bounds rational number expansion before schema or argument validation; inputs must be decoded with UseNumber, and it is a resource guard that never changes values.
- **Remote MCP numeric budget bounds rational expansion** (`aitools.ValidateRemoteMCPNumericBudget`): aitools.ValidateRemoteMCPNumericBudget parses only the exponent magnitude of already syntax-checked JSON numbers and stops at the remaining budget before multiplication could overflow an int.
- **Remote MCP headers are canonicalized before binding** (`aitools remote MCP header binding`): Remote MCP header preparation canonicalizes header names and rejects case variants because http.Header.Set would make case-variant map keys overwrite each other nondeterministically and change the prepared binding.
- **Tool resolution is a pure shared decision** (`aitools (package)`): Package aitools is deliberately pure so authorization, child transaction checks, and runtime injection compute the exact same effective tool set.
- **Coordination tool registry stays on for AI children** (`aitools.RegistersCoordinationTools`): aitools.RegistersCoordinationTools keeps the coordination tool registry for AI child Tasks even when implicit injection is disabled; disabling injection only narrows the selected list so explicitly selected coordination tools stay platform-provided.
- **Implicit tools are distinguished from Tool CR references** (`aitools.IsImplicitTool`): aitools.IsImplicitTool tells authorization which names Orka injects versus Tool CR references, without broadening implicit capabilities.
- **Runtime Agents use their runtime's tool policy** (`aitools.usesAIWorkerToolRegistry`): aitools.usesAIWorkerToolRegistry returns false for any Agent with spec.runtime, even without a Task, because runtime Agents follow their runtime's tool policy.
- **External runtimeRef profiles receive no implicit tools** (`aitools.injectsChildMessagingTools`): aitools.injectsChildMessagingTools injects messaging tools only for labeled children of built-in ACP runtimes; external runtimeRef profiles own their tool policy and receive no implicit tools.
- **Remote MCP ceiling is enforced outside Resolve** (`aitools.Resolve`): aitools.Resolve returns an ordered, de-duplicated tool list but cannot distinguish remote MCP backends from legacy Tools by name, so consumers loading Tool CRs must also call ValidateRemoteMCPSelection. Container Tasks expose no AI tools.
- **Memory consolidation runs expose no tools** (`aitools.Resolve`): aitools.Resolve returns no tools for memory consolidation Tasks (ADR 0051) regardless of Agent or Task lists, so they never freeze or dispatch connector tools they cannot use.
- **Substrate MCP egress Secrets require transaction authority** (`aitools.SubstrateMCPEgressCredentialSecretNames`): aitools.SubstrateMCPEgressCredentialSecretNames lists Secrets the Substrate egress gateway injects into a Substrate MCP actor's requests; transaction authority must cover them exactly like spec.http.authSecretRef.
- **Substrate MCP egress Secrets require transaction authority** (`aitools.SubstrateMCPEgressCredentialSecretNames`): aitools.SubstrateMCPEgressCredentialSecretNames returns each shared Secret once in rule order so callers make one access check per Secret.

### `internal/approvals`

- **Permission approvals belong to the requester** (`approvals.KindPermission`): An approval of kind approvals.KindPermission holds an agent runtime's permission request for the Task's requester, and only that requester may decide it.
- **Approval call bindings store only digests** (`approvals.CallBinding`): approvals.CallBinding identifies the original harness v2 call using digests of runtime-supplied identifiers, so public event sanitization can neither change the binding nor expose private text; the broker keeps the executable inputs in a Task-owned Secret, never in the event.
- **Duplicate approval requests are idempotent** (`approvals.Derive`): approvals.Derive ignores any approval-requested event whose approval ID already exists, so replayed request events can never reset a terminal decision back to pending.
- **Approval targets store only argument digests** (`approvals.ApprovalTarget`): approvals.ApprovalTarget stores a digest of the target arguments and a sanitized, bounded preview, never the raw side-effect payload, so approval events can be persisted without leaking secrets.
- **Empty approval arguments hash as {}** (`approvals.TargetArgsDigest`): approvals.TargetArgsDigest canonicalizes empty arguments to an empty JSON object before hashing, matching LLM tool-call semantics so an omitted and an empty argument object bind the same approval.
- **Approval metrics count committed decisions once** (`approvals.RecordDecision`): approvals.RecordDecision may only be called for a newly committed terminal event: callers exclude duplicate appends and wait for the (possibly grouped) append that wrote it to commit. Reading or deriving approval state must never record an observation.
- **Approvals bind the executed request** (`approvals.TargetArguments`): approvals.TargetArguments strips the body auth key and folds URL-template parameters plus the template into the reserved __orkaApprovalURL field; both worker and controller digest this view, so an approval binds exactly the request the controller executes.
- **Connector approvals bind link and policy** (`approvals.ConnectorTargetSpecDigest`): approvals.ConnectorTargetSpecDigest digests a connector-backed Tool's spec together with the credential-injection policy and the Connection identity frozen at dispatch, so a Job re-created after a re-link or policy change produces a different digest and needs a fresh approval.
- **Re-linking a Connection voids approvals** (`approvals.ConnectorTargetSpecDigest`): approvals.ConnectorTargetSpecDigest includes the Connection's grant sequence, binding an approval to one consent: re-linking the same Connection object requires a fresh decision.

### `internal/artifactcap`

- **Retirement grace outlives capabilities** (`artifactcap.MinimumRetirementGrace`): artifactcap.MinimumRetirementGrace is MaxCapabilityTTL plus MaxClockSkew so a retired identity stays blocked until every capability that could have been issued before retirement has expired.
- **Reserve before returning a capability** (`artifactcap.CapabilityReservationRecorder`): artifactcap.CapabilityReservationRecorder persists a digest reservation before a capability is handed to a caller; reservations keep cross-identity objects live until the capability expires or its identity is retired.
- **Artifacts are reclaimed only after retirement** (`artifactcap.Collector`): artifactcap.Collector reclaims artifact objects and replay records only after the controller explicitly retires their immutable Task/publication identities. The store and retention format shipped together in the harness v2 hard cutover, so there is no pre-retention ledger to backfill.
- **Retention sweeps run on the leader** (`artifactcap.Collector.NeedLeaderElection`): artifactcap.Collector runs periodic sweeps only on the controller leader; the artifact-root filesystem lock still protects transport during rolling-update overlap when two controllers share the volume.
- **Reservations take the exclusive root lock** (`artifactcap.Collector.Reserve`): artifactcap.Collector.Reserve persists one exact capability reference under the exclusive artifact-root lock, serializing reservation publication with reclamation; transport operations take the fair shared side of the same lock.
- **Retire is a caller-asserted terminal step** (`artifactcap.Collector.Retire`): artifactcap.Collector.Retire persistently blocks the given immutable identities; callers must first establish that no attempt, publication, external effect, or outbox recovery can need them again. Reclamation of their unshared objects happens later in Sweep.
- **Retirement defers reclamation** (`artifactcap.Collector.Retire`): artifactcap.Collector.Retire only records retirements and keeps objects and replay records through the maximum capability lifetime, giving every capability issued to another live identity time to start and persist its own replay reference.
- **Sweep resumes reclamation after crashes** (`artifactcap.Collector.Sweep`): artifactcap.Collector.Sweep resumes crash-interrupted reclamation and prunes retirement tombstones only after the maximum capability lifetime has elapsed.
- **Sync removals before dropping replay records** (`artifactcap.Collector.removeRetiredArtifacts`): Artifact retention syncs the metadata and object directories after removing retired files and before deleting the replay records that identify crash-recovery candidates, so a crash never loses track of half-removed artifacts.
- **fsGroup permission repair stays fail-closed** (`artifactcap.secureManagedArtifactFile`): artifactcap.secureManagedArtifactFile chmods an existing controller-owned regular file back to 0600 only to undo group bits a Kubernetes fsGroup mount adds; other-accessible files, symlinks, and non-regular files are rejected, and chmod uses the O_NOFOLLOW descriptor.

### `internal/gateway`

- **Service adapters are authenticated by TLS DNS name** (`gateway.EndpointResolver.Resolve`): gateway.EndpointResolver.Resolve targets https://<service>.<namespace>.svc because Service selectors only constrain routing; TLS authentication of the Service DNS name is what prevents a relabeled backend Pod from receiving the outbound bearer token.
- **Missing gateway CRDs are a staging state** (`gateway.ErrGatewayPrerequisitesUnavailable`): gateway.ErrGatewayPrerequisitesUnavailable marks missing or incompatible gateway/Task CRDs, which may be intentionally staged during an upgrade (ADR 0013); every other prerequisite error is treated as transient or operational. See [ADR 0013](0013-stage-gateway-resource-rollout.md).
- **Gateway requires Task CRD session-cutoff schema** (`gateway.RequireTaskSessionCutoffSchema`): gateway.RequireTaskSessionCutoffSchema refuses to start gateway controllers unless the installed Task CRD carries the session-cutoff schema annotation, so the API server preserves the gateway transcript policy fields instead of pruning them on an older CRD (ADR 0013/0020). See [ADR 0020](0020-gateway-session-canonical-history.md).
- **Reply origin is resolved before tool freeze** (`gateway.Service.ResolveReplyEligibility`): gateway.Service.ResolveReplyEligibility resolves durable origin before tool configuration is frozen; readiness and interim capability are admission gates, not origin, so temporary withdrawal must not freeze a tool-less execution. ErrNotReady means dispatch created but has not linked the Task, and callers must defer; metadata may locate a pending event but never grants access (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Fallback origin lookup uses full identity checks** (`gateway.Service.resolveReplyOrigin`): gateway.Service.resolveReplyOrigin falls back to the annotated event when the task index misses, because dispatch may link the Task between reads; the fallback applies the same durable ownership and live identity checks as an indexed lookup.
- **Origin proof is not an admission grant** (`gateway.TaskReplyOrigin`): gateway.TaskReplyOrigin authenticates origin only and carries no admission grant, routing, content or quota; every Budget and Enqueue authorizes afresh (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Prepared origin is single-request state** (`gateway.PreparedTaskReplyOrigin`): gateway.PreparedTaskReplyOrigin must be consumed inside the caller's authorized task-data transaction with its revocation fence and must never be retained across requests.
- **Live identity checks run outside the writer** (`gateway.Service.PrepareTaskReplyOrigin`): gateway.Service.PrepareTaskReplyOrigin performs Kubernetes live identity checks outside the SQLite writer so the writer never blocks on API reads (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Writer rechecks durable state only** (`gateway.Service.ReadPreparedTaskReplyOrigin`): gateway.Service.ReadPreparedTaskReplyOrigin rechecks durable ownership and lifecycle inside the authorized writer and performs no Kubernetes reads or budget/admission gates there (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Index-miss fallback must not become a label grant** (`gateway.replyOriginLookupMiss`): The replyOriginLookupMiss test store models a task-index miss just before dispatch commits the link; the fallback must still read the real durable event and must never turn Task labels into a grant.
- **Task-pass credentials are operator-mounted** (`gateway.Service.TaskPassCredentials`): gateway.Service.TaskPassCredentials are controller-mounted, per-Gateway-UID credentials; they are never delivery bearers or Secrets in Task/Tool namespaces, so namespace users cannot read or substitute them.
- **Gateway service runs only on the leader** (`gateway.Service.NeedLeaderElection`): gateway.Service.NeedLeaderElection returns true so dispatch, delivery and maintenance run on one replica; durable claims still give crash recovery, but leader election is what makes namespace Task-capacity checks replica-safe.
- **Cleanup receipts outlive Task deletion** (`gateway.Service.pruneGatewayTaskCleanupReceipts`): gateway.Service.pruneGatewayTaskCleanupReceipts keeps a receipt until the exact Task UID is gone from a live API read, even past retention while the Task is deleting, and never infers absence from the cache, because a lagging informer must not strand a Task by losing its deletion authority.
- **Receipt scan advances past failures** (`gateway.Service.pruneGatewayTaskCleanupReceipts`): gateway.Service.pruneGatewayTaskCleanupReceipts advances its cursor even past retained receipts and failed reads/deletes so one stuck entry cannot starve the rest; failed entries are retried after the scan wraps.
- **Session cleanup cursor uses raw query progress** (`gateway.Service.cleanupRetainedGatewaySessions`): gateway.Service.cleanupRetainedGatewaySessions advances by raw query progress, including rows excluded for invalid ownership, so blocked candidates are retried on wrap without stopping later Sessions or Task receipt maintenance.
- **Compaction receipts preserve Task deletion authority** (`gateway.Service.gatewayTaskCompactionArchived`): gateway.Service.gatewayTaskCompactionArchived uses compaction receipts to keep exact Task deletion authority after event deduplication expires, including Tasks that never acquired a SessionTurn; it only requests ordinary deletion, leaving runtime and archive finalizers to decide when the Task is removed.
- **Archive receipts allow deletion after long outage** (`gateway.Service.gatewayTaskCleanupArchived`): gateway.Service.gatewayTaskCleanupArchived relies on archive receipts that outlive bounded event tombstones, so a controller offline for the whole tombstone window can still request Task deletion.
- **Invalid prompt key means not archived** (`gateway.Service.gatewayTaskCleanupArchived`): gateway.Service.gatewayTaskCleanupArchived treats a prompt-attempt key that fails canonicalization as not archived, since no admitted prompt can have a matching archive; this fails safe by not deleting the Task.
- **Authenticate before readiness checks** (`gateway.Service.AdmitEvent`): gateway.Service.AdmitEvent authenticates the inbound bearer before mutable readiness checks so an exact retry of an already-committed event still receives its durable duplicate acknowledgement (ADR 0012). See [ADR 0012](0012-gateway-inbox-outbox-semantics.md).
- **Fenced admission is not a Session conflict** (`gateway.Service.AdmitEvent`): gateway.Service.AdmitEvent checks store.ErrFenced before ErrConflict: a replaced controller's fenced write also matches ErrConflict but says nothing about Session ownership, so the event is neither recorded as rejected nor acknowledged and the adapter retries it against the current controller.
- **Linking an existing Task needs no capacity** (`gateway.Service.namespaceTaskCapacityAvailable`): gateway.Service.namespaceTaskCapacityAvailable admits immediately when the deterministic Task already exists, because linking it creates no new work.
- **Count unphased Tasks against capacity** (`gateway.Service.namespaceTaskCapacityAvailable`): gateway.Service.namespaceTaskCapacityAvailable counts Tasks with an empty phase as active, because the controller initializes it to Pending shortly after create and one dispatch batch must not create more non-terminal Tasks than the limit.
- **Recovery keeps the created Task type** (`gateway.Service.reconcileExistingDispatchTask`): gateway.Service.reconcileExistingDispatchTask materializes the expected Task with the existing Task's type, since Task type is immutable and Agent edits after creation must not reroute recovery.
- **Ambiguous create links the read Task** (`gateway.Service.createOrFindGatewayTask`): After a failed Create, gateway.Service.createOrFindGatewayTask re-reads the deterministic Task and, if it matches, links it, because the Create response may be ambiguous even though the API server committed the Task.
- **Unknown create errors keep the dispatch claim** (`gateway.Service.createOrFindGatewayTask`): When Task create fails with an error that is not definitively a rejection, gateway.Service.createOrFindGatewayTask keeps the Dispatching claim intact so lease recovery reconciles the possibly-committed Task before requeueing.
- **Failed link leaves the Task for recovery** (`gateway.Service.linkGatewayTask`): If linking a gateway event to its Task fails, gateway.Service.linkGatewayTask returns an error and leaves the Task in place, because a reclaimed owner may already be linking it; lease recovery reconciles the exact UID instead of deleting adopted work.
- **Pre-execution failures do not pin soul absence** (`gateway.Service.projectTerminal`): gateway.Service.projectTerminal marks a failed AI Task as soul-unbound only if it failed before binding and execution and no Job controlled by the Task exists in a live read, since a lost start-status write could hide an earlier no-soul Job; read failures retry projection rather than pin the wrong identity.
- **Eligibility reads finish before the request timeout** (`gateway.Service.DeliverOnce`): gateway.Service.DeliverOnce completes interim-message eligibility reads before starting the adapter request timeout, so slow Kubernetes reads cannot consume the adapter's send budget.
- **Correlate the Task before committing delivery** (`gateway.Service.completeGatewayDelivery`): gateway.Service.completeGatewayDelivery patches Task correlation before marking a terminal delivery Delivered; if the patch fails the Sending lease expires and the same idempotent delivery is replayed, converging correlation without a second provider send (ADR 0012). See [ADR 0012](0012-gateway-inbox-outbox-semantics.md).
- **Task match ignores control fields** (`gateway.gatewayTaskMatchesExpected`): gateway.gatewayTaskMatchesExpected compares only ExecutionInputs, because control fields such as suspend can change after creation and a paused Task is still the deterministic Task its event created, not a name collision.
- **Task names include the admission instant** (`gateway.gatewayTaskName`): gateway.gatewayTaskName includes the admission timestamp so names stay deterministic for retries while the event or tombstone exists, but a deliberately re-admitted event after the deduplication window does not collide with the earlier Task.
- **Keep real listeners outside synctest** (`gateway.TestServiceStartDispatchesAndDeliversDuringBlockedMaintenance`): TestServiceStartDispatchesAndDeliversDuringBlockedMaintenance builds the fixture's real HTTP listener outside the synctest bubble and routes deliveries through the adapter handler without a socket.
- **Start waits for bounded mutations after cancel** (`gateway.gatewayMaintenanceBlocker`): The gatewayMaintenanceBlocker test models a bounded runtime mutation that finishes after cancellation; gateway.Service.Start must not return before such in-flight work completes.
- **Unsupported capability is its own error** (`gateway.ErrInterimDeliveryUnsupported`): gateway.ErrInterimDeliveryUnsupported identifies an absent adapter interimDelivery capability separately from Task lifecycle or idempotency conflicts, even though both map to HTTP 409.
- **Message receipt acknowledges admission** (`gateway.TaskMessageReceipt`): gateway.TaskMessageReceipt acknowledges durable admission, not provider delivery; a replay returns the retained row's current status without requeueing it (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Prepared message is single-request state** (`gateway.PreparedTaskMessage`): gateway.PreparedTaskMessage carries only controller-derived admission data, prepared during live authorization and enqueued in the authorized task-data writer; it is not a worker credential and must not be retained across requests.
- **Worker APIs use split prepare/enqueue** (`gateway.Service.EnqueueTaskMessage`): gateway.Service.EnqueueTaskMessage is only for an already-authorized exact Task identity; worker APIs must use PrepareTaskMessage and EnqueuePreparedTaskMessage so the Job revocation fence runs inside the writer.
- **Callers supply no routing or policy** (`gateway.Service.PrepareTaskMessage`): gateway.Service.PrepareTaskMessage performs live Kubernetes checks outside the SQLite writer and accepts no routing or controller policy from the caller; all routing derives from the admitted event (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Bound raw interim text before sanitizing** (`gateway.Service.PrepareTaskMessage`): gateway.Service.PrepareTaskMessage checks the 16 KiB limit on raw content before sanitization can shrink it and rejects oversize content rather than truncating it (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Durable event state is the terminal cutoff** (`gateway.Service.EnqueuePreparedTaskMessage`): gateway.Service.EnqueuePreparedTaskMessage performs only store work in an existing authorized writer; durable event state is the terminal-race cutoff, and there is deliberately no transaction spanning Kubernetes and SQLite (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Admission time taken in the writer** (`gateway.Service.EnqueuePreparedTaskMessage`): gateway.Service.EnqueuePreparedTaskMessage stamps admission time inside the writer rather than reusing the earlier live-read time, so expiry and ordering reflect actual admission.
- **Revalidate interim messages before send** (`gateway.Service.validateMessageDelivery`): gateway.Service.validateMessageDelivery revalidates immediately before network dispatch; terminal Tasks stay valid because accepted messages drain before final/error, while missing or replaced identities, deleting Tasks or withdrawn capability abandon the message and never downgrade it (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Budget reveals only policy and receipt existence** (`gateway.TaskMessageBudget`): gateway.TaskMessageBudget exposes only the limit and receipt existence, never message text or routing.
- **Prepared budget is short-lived** (`gateway.PreparedTaskMessageBudget`): gateway.PreparedTaskMessageBudget is short-lived live authorization state that must be read inside the caller's authorized task-data access, like message enqueue.
- **Tests use the real create-before-link window** (`gateway.TestGatewayReplyEligibilityPendingLinkThenBound`): TestGatewayReplyEligibilityPendingLinkThenBound observes the real dispatch window between Task create and event link via a client interceptor, rather than simulating ownership with labels, so it proves labels never grant budget access.
- **Dispatch rechecks runtime-only Agent defaults** (`gateway.TestGatewayNativeAIRejectsRuntimeOnlyDefaultsAtDispatch`): Gateway dispatch revalidates the Agent at dispatch time because readiness can lag an Agent edit made after admission; it must fail rather than create a Task that drops a runtime-only default such as agentRuntimeMaxTurns.
- **Advance projection clock after link** (`gateway.TestExpiredLinkedTaskReleasesSessionWithVisibleError`): TestExpiredLinkedTaskReleasesSessionWithVisibleError advances the projection clock only after dispatch has linked the Task, so admission and SQLite I/O cannot race a millisecond expiry on slow CI.
- **Fenced admission is retried by the adapter** (`gateway.Service.AdmitEvent`): A fenced gateway admission comes from a replaced controller; it is neither recorded as rejected nor acknowledged, so the adapter retries the event against the current controller.
- **Task grants freeze from UID-linked events** (`gateway.TaskGrant`): gateway.TaskGrant is nonsecret authority frozen only from a UID-linked durable event; the controller narrows Tools and Deadline before persisting the snapshot.
- **Delegation pins a frozen parent snapshot** (`gateway.TaskGrantParent`): gateway.TaskGrantParent pins controller-protected delegation to a frozen parent snapshot by digest and contains no credential or provider identity.
- **Grants never come from markers or Sessions** (`gateway.Service.ResolveTaskGrant`): gateway.Service.ResolveTaskGrant never trusts Task markers or a shared Session as authority; grants come only from the Task's UID-linked delegatedText event.
- **Parent grant check covers root origin only** (`gateway.Service.ValidateParentTaskGrantOrigin`): gateway.Service.ValidateParentTaskGrantOrigin checks only the retained root origin; the controller must first verify a live ancestor (Running, or parked for the exact child) with its original binding, and the check never reopens root reply or terminal Task tool authority.
- **Pass endpoints use the gateway origin** (`gateway.Service.taskGrantFromEvent`): gateway.Service.taskGrantFromEvent fixes the task-pass endpoint to the authenticated gateway's scheme and host, so no event or Task field can redirect pass issuance.
- **Task-pass credentials pin their origin** (`gateway.TaskPassCredential`): gateway.TaskPassCredential binds the operator's credential to its trusted HTTPS origin, so a namespace editor cannot retarget it by editing the same Gateway's spec.
- **Task-pass credential values stay out of objects** (`gateway.LoadTaskPassCredentials`): gateway.LoadTaskPassCredentials reads an operator-mounted Gateway-UID-to-credential map, and credential values never enter Kubernetes objects or error messages.
- **Issued passes use a JSON-stable alphabet** (`gateway.validIssuedTaskPass`): gateway.validIssuedTaskPass requires issued passes to use a JSON-stable bearer alphabet so standard JSON encoding cannot escape characters and hide the literal token from the executor's existing redaction.
- **Grants are revalidated before issue and send** (`gateway.Service.ValidateTaskGrant`): gateway.Service.ValidateTaskGrant rechecks Task liveness and durable origin immediately before both pass issuance and tool send; child and unbound Tasks have no authority.
- **Task passes are single-shot and unpersisted** (`gateway.Service.TaskPass`): gateway.Service.TaskPass acquires one bounded pass, never retries issuance or persists tokens, and requires a controller callback that revalidates the complete live chain first.

### `internal/gateway/conformance`

- **Reconciliation probes never send deliveries** (`conformance.Probe`): conformance.Probe performs only authenticated health and capability requests and never sends a delivery, because Gateway reconciliation calls it repeatedly and a probe must not cause a provider-side send.
- **Interim probe precedes final and is capability-gated** (`conformance.Check`): conformance.Check sends the interim message probe before the final delivery for the same event, reusing the private fixture routing, and never sends any message-kind probe (even a negative one) to an adapter that does not advertise interimDelivery (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Interim replay after terminal keeps its receipt** (`conformance.Check`): conformance.Check replays the interim message after the terminal delivery and requires the same provider message ID: an adapter must return the original receipt rather than send again or reject once the event is terminal (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Conformance output is sanitized at the boundary** (`conformance.SanitizeCheckResult`): conformance.SanitizeCheckResult is a final defense applied before CLI or test-harness serialization; it re-redacts the bearer and bounds text even when a caller constructs a CheckResult directly, so output safety does not depend on every check path sanitizing.
- **Mask fixture identities before truncating diagnostics** (`conformance.Target.safeError`): conformance.Target.safeError masks delivery-fixture identities in the full diagnostic before truncating it, because truncating first could leave an unmatched prefix of a private routing identity in the output.
- **Fixture requests close every connection** (`conformance.fixtureTransport.RoundTrip`): conformance.fixtureTransport.RoundTrip forces Request.Close because an adapter could echo private routing in unsolicited HTTP/1.x bytes, and net/http's idle connection reader would log those bytes; closing each connection prevents that leak.
- **Fixture validates original identity values** (`conformance.DeliveryFixture.deliveryRequest`): conformance.DeliveryFixture.deliveryRequest checks the untrimmed fixture identities (including the optional thread ID) for length, UTF-8 and control characters, because V1 validation trims required identities and does not bound the thread, while the fixture transmits the original values.
- **Mask whole fields before bearer redaction** (`conformance.DeliveryFixture.maskResultFields`): conformance.DeliveryFixture.maskResultFields replaces an entire field that contains any fixture identity before bearer sanitization, because partial replacements can hide overlapping identities and expose their remaining fragments.
- **Match repeatedly quoted identities** (`conformance.DeliveryFixture.maskResultFields`): conformance.DeliveryFixture.maskResultFields matches identities under repeated strconv quoting, since HTTP and JSON errors can quote an already quoted value; escaping only grows the fragment, so the field length bounds the loop.
- **Check each nested decoding separately** (`conformance.DeliveryFixture.maskResultFields`): conformance.DeliveryFixture.maskResultFields checks path-unescaped, query-unescaped (+ as space) and string-unquoted candidates separately, so an identity containing literal escape text is not missed when URL and string quoting are nested; masking never changes transmitted routing.
- **Nested decoding is bounded and fails closed** (`conformance.DeliveryFixture.maskResultFields`): conformance.DeliveryFixture.maskResultFields stops after 8 decoding candidates and redacts the whole field, bounding work on nested encodings without ever emitting an unchecked field.

### `internal/gateway/protocol`

- **Reject invalid UTF-8 and lone surrogates** (`protocol.ValidJSONUnicode`): protocol.ValidJSONUnicode rejects invalid UTF-8 and unpaired UTF-16 escapes before encoding/json can silently replace them with U+FFFD, and checks JSON syntax first so escape scanning never treats malformed input as valid text.
- **Task-pass tools call one fixed path** (`protocol.TaskToolPath`): protocol.TaskToolPath is the only path a gateway task-pass Tool may call; tool endpoints are fixed per tool name under /v1/task-tools/ at the authenticated gateway origin, never caller-chosen.
- **orka.gateway.v1 is frozen** (`protocol.Version`): protocol.Version (orka.gateway.v1) is a frozen adapter contract; new behavior is added through optional capabilities and kinds under the same discriminator, not by changing the version (ADR 0032).
- **Plain text events carry no delegated authority** (`protocol.EventTypeText`): protocol.EventTypeText events carry no delegated tool authority; only delegatedText may carry a gatewayGrantRef.
- **delegatedText requires a nonsecret grant reference** (`protocol.EventTypeDelegatedText`): protocol.EventTypeDelegatedText requires a generation-bound, nonsecret gatewayGrantRef in metadata, and ValidateEvent rejects the ref on any other event type, so tool authority is never inferred from plain text events.
- **Interim message kind is capability-gated** (`protocol.DeliveryKindMessage`): protocol.DeliveryKindMessage is a nonterminal assistant message that may be sent only to adapters advertising interimDelivery (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Retryable errors retry the same delivery ID** (`protocol.DeliveryStatusRetryableError`): protocol.DeliveryStatusRetryableError tells Orka to retry with the same delivery ID, which adapters use for idempotency so a retry never becomes a second provider send (ADR 0012). See [ADR 0012](0012-gateway-inbox-outbox-semantics.md).
- **Ingress acknowledges durable admission only** (`protocol.IngressResponse`): protocol.IngressResponse acknowledges durable admission of the event without waiting for Task execution (ADR 0012). See [ADR 0012](0012-gateway-inbox-outbox-semantics.md).
- **Normalization trims but preserves identity case** (`protocol.NormalizeEvent`): protocol.NormalizeEvent only trims boundary whitespace and preserves provider-owned identity case; it rejects metadata exceeding the raw entry bound or whose keys collide after trimming, so normalization cannot merge distinct keys.

### `internal/gateway/referenceadapter`

- **Reference adapter never evicts receipts** (`referenceadapter.maxRetainedDeliveries`): referenceadapter.maxRetainedDeliveries bounds all retained identities, including failed fixture attempts, and the adapter rejects new ones at the bound instead of evicting receipts, because forgetting a receipt could turn a retry into a duplicate provider send.
- **Recheck interim eligibility under the send lock** (`referenceadapter.Server.handleDelivery`): referenceadapter.Server.handleDelivery rechecks interim capability and terminal state under the send lock, because a delayed fixture message may race a terminal send for the same event.

### `internal/gateway/workerclient`

- **Reply transport is native-worker only** (`workerclient (package)`): Package workerclient implements the native worker's task-bound gateway reply transport; brokered ACP executions use their authorized broker transaction instead of this HTTP path (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Worker reply client uses projected tokens only** (`workerclient.Config`): workerclient.Config takes controller-owned identity and a projected Pod token path; raw environment tokens are deliberately unsupported.
- **Unavailable never implies origin** (`workerclient.ErrUnavailable`): workerclient.ErrUnavailable classifies optional service or transport failures; during bootstrap callers may omit the reply tool but must never treat this error as an origin grant (ADR 0032). See [ADR 0032](0032-gateway-interim-delivery.md).
- **Reply client never uses env proxies** (`workerclient.New`): workerclient.New clears the transport Proxy so the projected Pod credential is never forwarded through environment-configured proxies.
- **Origin auth retries 503 only, bounded** (`workerclient.Client.AuthenticateOrigin`): workerclient.Client.AuthenticateOrigin retries only HTTP 503, at most five attempts within ten seconds, because a fast Pod may start before Job identity is published; no failed response proves identity.
- **Controller error bodies are not copied to tools** (`workerclient.Client.request`): workerclient.Client.request never copies provider, authorization or upstream body diagnostics into tool-visible errors; only known codes are interpreted.
- **Only known codes count as rejections** (`workerclient.gatewayRejectionStatus`): workerclient.gatewayRejectionStatus accepts a rejection code only if it agrees with the controller's HTTP status, so arbitrary bodies cannot convert a transport or backend failure into a definitive non-admission result.

### `internal/githubauth`

- **GitHub subjects are numeric user IDs** (`githubauth.Issuer`): People signed in with GitHub use githubauth.Issuer as identity issuer and their numeric GitHub user ID as subject, because the ID survives a login rename (ADR 0037). See [ADR 0037](0037-github-sign-in.md).
- **GitHub calls never follow redirects** (`githubauth.Client.http`): githubauth.Client never follows HTTP redirects because every call carries a token or device code in its body or headers, and a 307/308 would replay it to another origin.
- **Token check authenticates as the app** (`githubauth.Client.CheckToken`): githubauth.Client.CheckToken verifies a token by authenticating to GitHub as Orka's own OAuth app, so a token another app obtained never passes (ADR 0037).
- **Allowed teams do not admit whole orgs** (`githubauth.Allowed`): githubauth.Allowed admits active members of any listed org or team; listing a team never admits that org's other members.
- **Membership failures are not verdicts** (`githubauth.Client.RequireMember`): githubauth.Client.RequireMember returns ErrNotMember only when GitHub said so and a different error when GitHub could not be asked; sign-in treats both as denial, while host refresh retries the latter instead of revoking access.
- **Rate limits never revoke membership** (`githubauth.Client.active`): githubauth.Client.active treats only a 404 as a not-member verdict; GitHub answers rate limits, including header-less secondary limits, with 403 or 429, so those return errors and must never end a member's access.
- **Device-flow polling ignores transient failures** (`githubauth.Client.PollDeviceFlow`): githubauth.Client.PollDeviceFlow treats a failed call, a 5xx, or a 429 as no verdict on the device code and keeps polling until GitHub answers or the code expires.
- **Device-flow errors decode from non-2xx bodies** (`githubauth.Client.do`): githubauth.Client.do still decodes JSON from non-2xx responses (ignoring decode failures) because GitHub's device flow reports errors as JSON with status 200 or 4xx.

### `internal/labels`

- **Platform identities are never lent to workers** (`labels.LabelPlatformIdentity`): labels.LabelPlatformIdentity marks Orka's own ServiceAccounts; their tokens carry platform authority, so OutboundAccessPolicies may not hand them to workers.
- **Brokered children record parent namespace** (`labels.AnnotationParentTaskNamespace`): labels.AnnotationParentTaskNamespace records the namespace of the Task a brokered child was delegated from, beside its UID, so a child created in another namespace can still find its parent.
- **Cancel requests are controller-written** (`labels.AnnotationCancelRequested`): labels.AnnotationCancelRequested records a verified parent's cancel_task request with the terminal message as its value; only controller identities may set it, and the Task controller completes cancellation through its normal terminal path.
- **requestedBy source is controller-written** (`labels.AnnotationRequestedBySource`): labels.AnnotationRequestedBySource records that spec.requestedBy was stamped by the API server from a verified identity; only controller identities may set it, and child Tasks inherit trust through their coordination parent.
- **requestedBy is proven by an HMAC stamp** (`labels.AnnotationRequestedByStamp`): labels.AnnotationRequestedByStamp is an HMAC over Task UID and requester sealed by the API server right after creating a stamped Task. Because admission is not retroactive, the source annotation alone proves nothing: a Task planted while admission was disabled carries no valid stamp.
- **Continuation labels are not authoritative** (`labels.LabelContinuationOf`): For parked-turn continuations the parked Task's status.wait is the authority; labels.LabelContinuationOf and the continuation annotations are informational and for selection only (ADR 0041). See [ADR 0041](0041-data-only-parked-turns.md).
- **Continuation chains cannot extend deadlines** (`labels.AnnotationContinuationChainDeadline`): labels.AnnotationContinuationChainDeadline carries the absolute RFC 3339 deadline inherited from the first Task of a continuation chain; it can only shorten the deadline derived from creation time and spec.timeout, never extend it.
- **Continuations are finalized until linked** (`labels.ContinuationLinkFinalizer`): labels.ContinuationLinkFinalizer keeps a continuation Task from disappearing before its parked predecessor durably records its UID; otherwise a continuation created then deleted in that window would look never-created and recovery would start the work again.
- **Suspend quota Leases are controller-only** (`labels.ACPSuspendQuotaLeaseNamePrefix`): Leases named with labels.ACPSuspendQuotaLeaseNamePrefix are class-owned suspension quota records that admission restricts to controller writes.
- **Retention fence Leases are controller-only** (`labels.ACPWorkspaceRetentionFenceLeaseNamePrefix`): Leases named with labels.ACPWorkspaceRetentionFenceLeaseNamePrefix are idle-expiry admission fences that admission restricts to controller writes.
- **AHP turn Tasks are private to the sender** (`labels.LabelAHPTurn`): Tasks labeled labels.LabelAHPTurn=true were created by an Agent Host Protocol turn, and the API shows them only to the person who sent that turn.
- **Chat Tasks pin the Session incarnation** (`labels.LabelChatSessionEpoch`): labels.LabelChatSessionEpoch stores the chat Session's creation time (as SessionEpoch formats it) so a chat deleted and recreated under the same name is a different incarnation and cannot claim the old one's Tasks.
- **Chat Session namespace defaults to the Task's** (`labels.LabelChatSessionNamespace`): labels.LabelChatSessionNamespace names the namespace of the chat Session that created a Task, since a chat may create Tasks in other namespaces; a chat Task without it belongs to a chat in its own namespace.

### `internal/liveevents`

- **Live events are a lossy in-process tap** (`liveevents (package)`): Package liveevents fans out running-Task events to in-process consumers during a turn as a lossy tap beside the durable execution event journal: a lagging consumer loses its subscription and must reload from the journal, and nothing survives a restart or leader change.
- **Live events are ordered and pre-redacted** (`liveevents.Event`): liveevents.Event values are published in the order the controller received them, and runtime content is redacted before publication.
- **Expired approvals are rejections** (`liveevents.ApprovalExpired`): liveevents.ApprovalExpired means the permission request was rejected because nobody answered in time; expiry never approves.
- **Approval input is redacted and ephemeral** (`liveevents.Approval.Input`): liveevents.Approval.Input carries the redacted tool-call input only on the live stream; it is never stored.
- **Nil Broker drops events** (`liveevents.Broker`): A nil liveevents.Broker drops everything, so producers publish without nil checks; Publish and Subscribe must stay nil-safe.
- **Subscriptions start without replay** (`liveevents.Subscription`): A liveevents.Subscription receives a Task's events only from the moment it was created; there is no backlog replay, and consumers needing history read the journal.
- **Lagging subscribers are closed, not skipped** (`liveevents.Broker.Publish`): liveevents.Broker.Publish never blocks; a subscriber whose buffer is full is closed with ErrLagged instead of skipping the event, so a consumer never sees a stream with a silent gap.

### `internal/llm`

- **Fallback telemetry reports the primary provider** (`llm.FallbackProvider.TelemetryProviderName`): llm.FallbackProvider.TelemetryProviderName delegates to the primary provider so that error telemetry emitted before any concrete fallback response exists names the configured serving provider rather than the fallback(...) wrapper name.
- **Stream falls back only before output** (`llm.FallbackProvider.Stream`): llm.FallbackProvider.Stream switches to the next candidate only when Stream fails or the first meaningful chunk is an error; once a candidate has produced content, a tool call or Done, it is committed, because output already forwarded to the caller cannot be replaced by another provider.
- **Fallback may skip usage-only leading chunks** (`llm.FallbackProvider.Stream`): llm.FallbackProvider.Stream discards usage-only chunks that arrive before the first content, tool call, Done or error (firstStreamResult) because each provider's usage recorder retains that usage independently of which candidate the fallback selects; usage accounting does not depend on the fallback forwarding it.
- **Provider SDK clients share one HTTP client** (`llm.SharedHTTPClient`): llm.SharedHTTPClient returns a process-wide HTTP client so request-scoped provider SDK clients reuse connections. Credentials and middleware stay on each SDK client, never on this shared client, and callers must not mutate the returned client or its transport because every provider shares it.
- **Shared transport keeps a 10-minute header timeout** (`llm.sharedHTTPClient`): llm.sharedHTTPClient clones http.DefaultTransport once and sets ResponseHeaderTimeout to ten minutes, preserving the response-header deadline the OpenAI and Anthropic SDKs would otherwise apply, without creating a fresh connection pool each time credentials are resolved.
- **SystemPromptStable marks the cacheable system prefix** (`llm.CompletionRequest.SystemPromptStable`): llm.CompletionRequest.SystemPromptStable is the number of leading bytes of SystemPrompt that stay identical across requests (for example fixed instructions before a changing catalog); zero means no split. Providers whose caches need explicit breakpoints mark the end of this stable part, and providers that key caches use only this part.
- **TemperatureSet preserves an explicit zero** (`llm.CompletionRequest.TemperatureSet`): llm.CompletionRequest.TemperatureSet records that an in-memory caller explicitly chose a temperature, so an explicit 0 is sent rather than being indistinguishable from unset; it is not serialized.
- **Store is tri-state** (`llm.CompletionRequest.Store`): llm.CompletionRequest.Store is a pointer so an explicit stateless request (store=false) survives provider translation, while nil keeps each provider's default for existing callers.
- **ResponsesInput preserves native item order** (`llm.CompletionRequest.ResponsesInput`): llm.CompletionRequest.ResponsesInput marks requests that entered through Orka's compatible Responses endpoint; providers must preserve native input/output item order for them, though turn-based adapters such as Chat Completions may group adjacent input items.
- **Legacy positive temperature counts as set** (`llm.CompletionRequest.HasTemperature`): llm.CompletionRequest.HasTemperature is true when TemperatureSet is true or, for legacy callers that never set the flag, when Temperature is positive.
- **Ordered output items supplement aggregate fields** (`llm.AssistantOutputItem`): llm.AssistantOutputItem holds a provider's text and function output in native order for Responses callers, while existing consumers keep using the aggregate Content and ToolCalls fields; providers fill both.
- **Ordered assistant turn stays in one message** (`llm.Message.OutputItems`): llm.Message.OutputItems keeps an ordered assistant turn in a single message so context truncation keeps or drops its tool calls and adjacent results atomically; the field is in-memory only and never persisted.
- **Prompt size adds cache tokens only for exclusive counts** (`llm.promptTokens`): llm.promptTokens adds cache reads and writes back to the input count only when InputExcludesCache is set, as for Anthropic, whose input_tokens excludes cached tokens; providers whose input count already includes cache tokens report it unchanged.
- **Stream retries only before output** (`llm.RetryProvider.Stream`): llm.RetryProvider.Stream retries transient failures only until the provider emits content, a tool call, Done or an error as its first meaningful chunk; after that the attempt is committed and proxied, because output already sent to the caller cannot be replayed by a new attempt.
- **Usage-only chunks do not commit a stream attempt** (`llm.RetryProvider.Stream`): llm.RetryProvider.Stream ignores usage-only chunks when deciding whether an attempt has started, so a stream that reports usage and then fails is still retried; usage from the failed attempt is retained by the provider's usage recorder rather than by the forwarded stream.
- **Telemetry identity is separate from Provider.Name** (`llm.TelemetryIdentity`): llm.TelemetryIdentity lets a provider report its concrete OpenTelemetry GenAI provider name separately from Provider.Name(), which is user-facing (for example fallback(...) wrappers); Provider.Name() must not be repurposed for telemetry.
- **Known fixed stop reasons pass through telemetry** (`llm.unclassifiedProviderStopReasons`): llm.unclassifiedProviderStopReasons lists provider stop reasons and response statuses (Anthropic model_context_window_exceeded, OpenAI Responses in_progress and queued) that NormalizeCompletionOutcome does not classify; because they are fixed SDK enum values, telemetry reports them verbatim.
- **Unknown stop reasons collapse to unknown_stop_reason** (`llm.telemetryStopReason`): llm.telemetryStopReason reports any stop reason that is neither classified nor a known fixed enum value as unknown_stop_reason, because OpenAI-compatible endpoints can return arbitrary text there and telemetry must not carry unbounded or content-bearing values.
- **GenAI input tokens count the whole prompt** (`llm.setResponseAttributes`): llm.setResponseAttributes reports gen_ai.usage.input_tokens as PromptTokens(), the whole prompt including cache reads and writes, with the cache breakdown in separate attributes, because the GenAI convention counts every prompt token while Anthropic's raw input count excludes cached ones.
- **Tool calls and their results truncate atomically** (`llm.messageBlock`): llm.messageBlock groups an assistant message that has tool calls with all immediately following tool-result messages, and truncation keeps or drops each block whole, so the model never sees a tool result without its call or a call without its results.
- **Truncation cuts at quarter-budget boundaries** (`llm.cutsPerBudget`): llm.cutsPerBudget = 4 spaces the allowed truncation cut points a quarter of the token budget apart. Each move of the cut changes the prompt after the first message and costs one provider prompt-cache miss; quarter spacing keeps at least about three quarters of the budget of history while moving the cut only once per quarter budget of new conversation.
- **TruncateMessages keeps a stable cut for caching** (`llm.TruncateMessages`): llm.TruncateMessages always keeps the first message and the newest blocks that fit, dropping tool-call groups atomically, and places the cut at a quarter-budget boundary counted from the start of the conversation so a growing conversation keeps the same cut and cached prefix until newer messages outgrow it. Callers must truncate the whole conversation every step, never the output of an earlier truncation, or the quarter boundaries shift.
- **Usage persistence failures are never retried** (`llm.IsUsagePersistenceError`): llm.IsUsagePersistenceError identifies durable-accounting failures; ShouldRetry, ShouldFallback and the fallback stream path treat them as terminal so a failure to record usage never triggers another billable model call, even when it is joined with a provider error that would normally permit retry.
- **Usage is accounted per SDK HTTP attempt** (`llm.UsageHTTPMiddleware`): llm.UsageHTTPMiddleware opens a new durable usage observation for every HTTP request the SDK sends, because SDK-internal retries and API fallbacks can each incur usage even when only the last one reports counts. The middleware never reads request bodies, response bodies, headers or credentials.
- **Provider-internal probe usage is recorded** (`llm.RecordIntermediateUsage`): llm.RecordIntermediateUsage persists the usage of a successful SDK call that a provider consumes internally (such as the OpenAI Responses support probe before streaming) instead of returning it to the worker, so that billed usage is not lost.
- **Unreported token counts stay nil** (`llm.ReportedTokenCount`): llm.ReportedTokenCount returns nil when the provider did not report a field, so a missing cache breakdown is distinguishable from a reported zero in usage accounting and telemetry.
- **Usage ownership comes from the caller** (`llm.WithUsageRecorder`): llm.WithUsageRecorder enables durable usage accounting independently of tracing; the caller-supplied recorder carries verified ownership, and no provider- or user-supplied billing fields are trusted to establish it.
- **Detached streams keep only the usage recorder** (`llm.CopyUsageRecorder`): llm.CopyUsageRecorder carries the usage recorder into a context detached from the HTTP request so accounting continues for the stream, copying only the counts recorder and never the request or its credentials.
- **Usage accounting sits inside retry and fallback** (`llm.usageProvider`): llm.NewProvider wraps each concrete provider in llm.usageProvider before any retry or fallback decorator is applied, so every individual call, including rejected and cancelled attempts, gets its own durable usage identity.
- **Usage writes outlive call cancellation for 90s** (`llm.usageWriteTimeout`): llm.usageWriteTimeout bounds usage writes that run detached from the call's cancellation at 90 seconds, longer than the worker event recorder's connection retries, so a controller restart during a model call does not fail the call's accounting.
- **Rejoin persistence errors after SDK conversion** (`llm.usageProvider.Complete`): llm.usageProvider.Complete joins the call's recorded persistence error into the returned error because SDK error conversion can discard the type of an error returned by the usage middleware, which would otherwise make an accounting failure look retryable.

### `internal/llm/anthropic`

- **Anthropic stream idle timeout is ten minutes** (`anthropic.streamIdleTimeout`): anthropic.streamIdleTimeout abandons a stream after ten minutes without a byte. The API sends ping events while the model thinks, but proxies may buffer a whole turn and send nothing until it ends; ten minutes matches the SDK's whole-request timeout for the non-streaming request Complete used to send, so turns that finished before still finish. It is a variable only so tests can shorten it.
- **Streaming Complete needs its own stall guard** (`anthropic.idleGuard`): anthropic.idleGuard cancels the request context when the response body delivers no bytes for streamIdleTimeout. The SDK applies a request timeout to non-streaming requests but none to streaming ones, so without the guard a stalled upstream would hold Complete until the caller's context ends.
- **Idle timer resets on raw body reads** (`anthropic.idleGuard.middleware`): anthropic.idleGuard.middleware wraps the HTTP response body and resets the idle timer on every read, rather than on stream events, because the SDK consumes ping events without returning them; only body-level activity proves a thinking model's stream is still alive.
- **A slow reader is not a stalled upstream** (`anthropic.idleGuard.pause`): anthropic.idleGuard.pause stops the idle timer while a Stream chunk waits for the caller to take it, until the next body read, so time spent on the caller's side never counts toward streamIdleTimeout.
- **Strip trailing /v1 from Anthropic base URL** (`anthropic.NewProvider`): anthropic.NewProvider trims a trailing slash and a trailing /v1 from the configured base URL because the Anthropic SDK appends v1/messages itself; keeping /v1 would produce a doubled /v1/v1 path.
- **Anthropic Complete always streams** (`anthropic.Provider.Complete`): anthropic.Provider.Complete issues a streaming request and assembles the message from events. The SDK refuses a non-streaming request whose max_tokens could exceed its ten-minute HTTP timeout (about 21,333 tokens), and proxies such as Vekil give non-streaming requests far less time than streaming ones.
- **Idle stream fails as retryable 502** (`anthropic.Provider.Complete`, `anthropic.stalledStreamError`): When anthropic.Provider.Complete abandons a stream because the idle guard fired (and the caller's context is still live), it returns a ProviderError with status 502 so the retry layer may try again; a stalled stream, like a broken one, has shown the caller nothing.
- **Mid-stream connection break is retryable** (`anthropic.Provider.Complete`): anthropic.Provider.Complete marks a status-less stream error that occurs after message_start as HTTP 502 when the caller's context is still live. None of the partial output reached the caller, so it is safe to treat like a stream that ended early and let the retry layer retry.
- **Unfinished stream never returns partial output** (`anthropic.Provider.Complete`): anthropic.Provider.Complete fails with a retryable 502 when the stream ends without a stop reason or message_stop, even with no error, because a dropped connection can end a stream cleanly and returning the partial message would pass truncated output off as complete.
- **Responses output keeps model order** (`anthropic.Provider.Complete`): For ResponsesInput requests anthropic.Provider.Complete builds OutputItems that interleave text and tool calls in the order the model wrote them, matching what completeViaStream produces for a streamed turn, so the Responses API sees the same ordering regardless of path.
- **Failed attempts still report billed usage** (`anthropic.completionAccumulator.failed`): anthropic.completionAccumulator.failed returns the error together with the usage reported before the failure so usage accounting counts tokens the attempt was billed for, while leaving out partial content that callers must not use.
- **Parallel tool results share one user message** (`anthropic.buildMessages`): anthropic.buildMessages appends consecutive tool results to a single user message instead of one message per result, because splitting parallel tool results across messages teaches Claude to stop making parallel tool calls.
- **Tool schemas pass through as raw fields** (`anthropic.buildToolParams`): anthropic.buildToolParams sends every root field of a tool's JSON Schema through ToolInputSchemaParam.ExtraFields as raw JSON, because the SDK's typed fields omit root constraints such as $defs and additionalProperties and would also reformat numeric values.
- **Responses system messages hoist to system field** (`anthropic.buildRequestParams`): For ResponsesInput requests anthropic.buildRequestParams moves system/developer messages out of history into the top-level system blocks, because Responses keeps them in history while Anthropic accepts instructions only in its system field.
- **Three prompt-cache breakpoints per request** (`anthropic.markPromptCache`): anthropic.markPromptCache sets cache_control on the first system block (the stable prefix of a split system prompt, keeping tools and fixed instructions cached), the last system block (keeping the whole system prompt cached when history is truncated), and the last message block (advancing each tool-loop step). Anthropic caches nothing without explicit breakpoints and allows four, so this uses at most three.
- **Skip empty text blocks for cache_control** (`anthropic.markPromptCache`): anthropic.markPromptCache skips empty text blocks when placing the message breakpoint because the Anthropic API refuses cache_control on an empty text block.
- **In-stream error events map to HTTP statuses** (`anthropic.streamErrorStatus`): anthropic.streamErrorStatus maps the type of an error event received inside a stream to the HTTP status the API returns for the same error before a stream starts, so retry and fallback classify both alike.
- **In-stream timeout maps to 502, not 504** (`anthropic.streamErrorStatus`): anthropic.streamErrorStatus maps timeout_error to 502 rather than 504 because llm.ShouldRetry skips 504s on the assumption the SDK already retried them; the SDK retries pre-stream 504s but never an error event inside a stream.
- **Override 200 status of in-stream errors** (`anthropic.toProviderError`): anthropic.toProviderError replaces the SDK status with the mapped streamErrorStatus only when the status is below 400, because an error event inside a stream carries the stream's 200 status while a pre-stream error already has its real HTTP status.
- **Omit temperature for Claude Opus 4.7 and later** (`anthropic.acceptsSamplingParams`): anthropic.acceptsSamplingParams drops temperature for Claude Opus 4.7 and every later Claude model, which return HTTP 400 when it is set, instead of failing the request. It finds the Claude model name anywhere in the ID so Bedrock IDs, Vertex @snapshots and dotted proxy names match, while any non-Claude model behind an Anthropic-compatible endpoint keeps its temperature.
- **Claude 3 names keep temperature** (`anthropic.parseClaudeModel`): anthropic.parseClaudeModel reports false, so acceptsSamplingParams keeps temperature, for any family token other than opus/sonnet/haiku/fable/mythos because Claude 3 names put the version before the family (claude-3-7-sonnet); those older models accept temperature.
- **Date suffix is not a minor version** (`anthropic.parseClaudeModel`): anthropic.parseClaudeModel treats a third name part longer than two digits as a date, not a minor version, because names such as claude-opus-4-20250514 put a release date where later names put the minor version; such models accept temperature.
- **Fable and Mythos are newer than Claude 4** (`anthropic.claudeModel.atLeast`): anthropic.parseClaudeModel accepts every Fable and Mythos name without a version, including claude-mythos-preview, and claudeModel.atLeast treats them as newer than any Opus, Sonnet or Haiku version.
- **Default output limit depends on the model** (`anthropic.defaultMaxTokens`, `anthropic.recentMaxTokens`, `anthropic.legacyMaxTokens`): When a request sets no output limit, anthropic.defaultMaxTokens sends 64,000 (recentMaxTokens) to Claude 4.5 and later models and 4,096 (legacyMaxTokens) to any other name. Every Claude 4.5+ model accepts at least 64,000 output tokens, including through GitHub Copilot, which caps some there; thinking counts toward the limit, so a smaller one cuts replies short on models that always think, while the API charges only for tokens used and these models stop at the end of the context window instead of failing.
- **Broken-stream test overstates Content-Length** (`anthropic.TestCompleteRetriesBrokenStream`): anthropic.TestCompleteRetriesBrokenStream sets Content-Length far above the bytes it writes so the client reads an unexpected EOF after message_start; without the oversized header the stream would end cleanly and the test would exercise the unfinished-stream path instead of the transport-error path.

### `internal/llm/openai`

- **Transport-error test truncates a declared body** (`openai.TestResponsesChatTerminalTransportErrorAfterFinish`): openai.TestResponsesChatTerminalTransportErrorAfterFinish declares a Content-Length far larger than it writes and omits [DONE], so the client sees a transport error after the finish_reason chunk; this is what proves held tool calls are not released when the stream fails after finishing.
- **OpenAI provider auto-detects its API surface** (`openai.Provider`): openai.Provider probes the Responses API first and, when the endpoint reports it unsupported, permanently switches that provider instance to Chat Completions (stored atomically in Provider.mode), because many OpenAI-compatible endpoints implement only Chat Completions.
- **Prompt cache key hashes the stable conversation prefix** (`openai.Provider.promptCacheKey`): openai.Provider.promptCacheKey sends a key derived from the model, the stable part of the instructions and the first message (which truncation always keeps), so OpenAI routes every step of a conversation to the machine holding its cached prefix instead of spreading them. It is sent only to OpenAI's own API, because compatible servers and Azure API versions may reject an unknown field.
- **Cache key ignores the volatile system suffix** (`openai.Provider.promptCacheKey`): openai.Provider.promptCacheKey hashes only SystemPrompt[:SystemPromptStable] so that a changed tool catalog or other volatile suffix after the stable prefix keeps the conversation's existing cache key.
- **Azure deployment name is upstream-only** (`openai.Provider.requestModel`): openai.Provider.requestModel substitutes the Azure deployment name only for the upstream request, leaving the caller's logical model on the CompletionRequest so authorization, fallback and telemetry keep using it.
- **Azure OpenAI still reports Name openai** (`openai.Provider.Name`): openai.Provider.Name returns "openai" even for Azure because callers historically use it as the implementation family; the concrete GenAI provider identity comes from TelemetryProviderName instead.
- **403 means unsupported API only with explicit codes** (`openai.isUnsupportedAPIError`): openai.isUnsupportedAPIError treats 404 and 405 as an unsupported Responses API, but a 403 only when its code or message explicitly says the API surface is unsupported, because some gateways report unsupported surfaces as 403 while a plain 403 can also mean an auth or model entitlement failure that must not trigger a silent fallback.
- **Tool schema fields are sent as raw JSON** (`openai.rawToolParameters`): openai.rawToolParameters passes each top-level schema field as json.RawMessage because decoding into map[string]any rounds numbers through float64 and the SDK serializes json.Number as a string; raw fields keep schema constraints byte-exact.
- **Blank streamed Responses completion is incomplete** (`openai.normalizeResponsesStopReason`): openai.normalizeResponsesStopReason reports a completed but blank unordered streamed response as incomplete instead of stop, because streaming callers lack the agent loop's tool-free final-answer retry state and would otherwise accept an empty answer as final.
- **Merged call state keeps the longest argument prefix** (`openai.responseFuncCallTracker.merge`): When responseFuncCallTracker merges two states for the same call in ordered mode, it keeps the longest argument buffer, because getChecked already verified the fragments share a compatible prefix and item metadata can arrive late.
- **Ordered calls emit only after the item completes** (`openai.responseFuncCallTracker.emit`): openai.responseFuncCallTracker.emit withholds a function call in ordered (Responses) mode until its item is done and has an output index and call ID, because finalized arguments alone do not prove the call finished successfully and Responses callers may execute a call as soon as it is published.
- **Streamed calls meet the complete-response argument contract** (`openai.responseFuncCallTracker.emit`): In ordered mode openai.responseFuncCallTracker.emit requires arguments to decode to a JSON object before emitting, so calls recovered from stream fragments satisfy the same contract as calls in a complete response before the coordinator processes them; otherwise the stream fails.
- **Ordered incomplete supports only text token-budget** (`openai.handleResponsesStreamEvent`): For response.incomplete in ordered mode, the OpenAI Responses stream handler accepts only a max_output_tokens outcome with no function calls; anything else is reported as response.incomplete. The decision is made before message snapshots are completed so it cannot release queued function calls.
- **Explicit empty arguments must match fragments** (`openai.handleResponseFunctionCallArgumentsDone`): openai.handleResponseFunctionCallArgumentsDone recovers arguments from prior fragments only when the final arguments field is omitted; in ordered mode an explicitly empty snapshot is validated against every observed fragment rather than replaced.
- **Hold ordered position until call is ready** (`openai.handleResponseOutputItem`): openai.handleResponseOutputItem keeps an ordered function-call position open while the call is not emitted, because a compatible upstream may supply the call ID or name only in its terminal snapshot.
- **Omitted message status waits for terminal outcome** (`openai.handleResponseOutputItem`): openai.handleResponseOutputItem does not emit OutputItemDone for a finished message whose status is omitted; the status stays unresolved until the terminal event can supply it, so already-sent SSE never needs rewriting.
- **Responses history regroups for Chat Completions** (`openai.groupAssistantTurns`): openai.groupAssistantTurns merges consecutive assistant items from ordered Responses history into one assistant turn because Chat Completions represents assistant text and function calls together, and it copies ToolCalls slices so normalization never mutates the caller's history.
- **Chat fallback holds Responses tool calls until clean end** (`openai.Provider.streamChatCompletions`): For ResponsesInput requests openai.Provider.streamChatCompletions keeps the accumulated tool calls private until the stream ends cleanly with tool_calls, because Responses publishes executable function items immediately and the SDK's JustFinishedToolCall detects only delta transitions, not a successful terminal outcome, and cannot reliably represent parallel calls.
- **Validate every Chat tool call before releasing any** (`openai.validateResponsesChatToolCalls`): openai.validateResponsesChatToolCalls checks every call (non-empty ID and name, unique ID, object arguments) before any is released, so a malformed later call cannot leave an earlier executable call in a failed public Responses stream.
- **Grouping test uses spare slice capacity as a guard** (`openai.TestGroupAssistantTurns (provider_test.go)`): The provider_test.go case for grouping Responses assistant turns backs the first assistant ToolCalls with a two-element array sliced to length one, so if groupAssistantTurns appended in place instead of copying, the second call would overwrite the guard element and the test would detect mutation of the caller's history.
- **Responses output streams in item order** (`openai.orderedResponseSender`): openai.orderedResponseSender streams the current output item immediately and queues later items until their predecessors finish, because function arguments can finish out of order and their readiness must not change the assistant's output order. It applies only to requests entering through the Responses endpoint.
- **Item statuses freeze at queue entry** (`openai.orderedResponseSender.statuses`): openai.orderedResponseSender records an item's completion status when its OutputItemDone enters the queue, even while the item still waits for predecessors, so a later conflicting status for the same item fails the stream instead of silently changing it.
- **Terminal snapshot output is all-or-nothing** (`openai.orderedResponseSender.terminal`): openai.orderedResponseSender.terminal buffers every chunk produced while handling a terminal snapshot, which can close an earlier message and drain queued calls, and forwards them only after every snapshot and ordering check succeeds; an error or non-output terminal is forwarded alone.
- **Failed or refused terminals bypass the queue** (`openai.orderedResponseSender.chunk`): openai.orderedResponseSender.chunk forwards error chunks and terminals that do not allow output directly, so a failed or refused outcome never recovers queued output and is never replaced by a secondary ordering error raised while flushing.
- **Only success and token-budget terminals release output** (`openai.responsesTerminalAllowsOutput`): openai.responsesTerminalAllowsOutput lets buffered Responses output be released only for tool_calls, length (supported token-budget truncation) and normalized completed outcomes; missing, failed and refused terminals abort it.
- **Flush terminal-only items in index order** (`openai.orderedResponseSender.flush`): openai.orderedResponseSender.flush releases queued items in index order when a stream ends, because some compatible upstreams supply complete items only in the terminal response, and it leaves the last text item open so the terminal outcome can mark a token-budget-truncated item incomplete.
- **Empty messages keep their output slots** (`openai.orderedResponseSender.flush`): openai.orderedResponseSender.flush includes observed message indices that produced no chunks, because empty messages still mark item boundaries, including after the last text chunk, and must keep their positions during terminal recovery.
- **Empty predecessor messages are completed first** (`openai.orderedResponseSender.flush`): When flushing, openai.orderedResponseSender emits OutputItemDone for each empty observed message slot before releasing later output, and fails the stream with a missing-predecessor error when a gap has no observed message.
- **Observed final status survives omitted snapshots** (`openai.orderedResponseSender.flush`): openai.orderedResponseSender.flush closes the last open message with its previously observed status when the terminal omits snapshots, but leaves a message with unknown status open so the terminal outcome can infer it.
- **Mixed indexed and unindexed output fails closed** (`openai.responseOutputOrder`): openai.responseOutputOrder validates the index, identity and type relationship of every event before output reaches the queue. Compatible text-only streams may omit indices entirely, but a stream that mixes unindexed text with indexed items is rejected rather than risk a reordered success.
- **Item types bind by ID and index** (`openai.responseOutputOrder.bindType`): openai.responseOutputOrder.bindType records an inferred item type even before an event supplies an index, because later metadata may connect an ID-only event to an index-only event, and both observations must agree or the stream fails.
- **Early final statuses bind to item identity** (`openai.responseOutputOrder.observeStatus`): openai.responseOutputOrder.observeStatus keeps final statuses that arrive with an added snapshot, before parts finish or an index is known, tied to the same ID and index bindings, and rejects any later conflicting status.
- **Nonempty terminal snapshot must cover observed items** (`openai.responseOutputOrder.validateTerminalMembership`): openai.responseOutputOrder.validateTerminalMembership accepts a terminal with no output snapshot, since compatible servers may omit it, but treats a nonempty snapshot as authoritative: it must account for every observed output index and message identity.
- **ID-only membership check applies to messages** (`openai.responseOutputOrder.validateTerminalMembership`): openai.responseOutputOrder.validateTerminalMembership checks ID-only membership only for messages, because the function-call tracker reconciles ID-only calls through call_id while messages have no alternate identity.
- **Index zero may identify the unindexed message** (`openai.responseOutputOrder.eventIndex`): Once a stream is in unindexed-text mode, openai.responseOutputOrder.eventIndex accepts output_index 0 on a message event as referring to the existing single unindexed message, keeping its text and status state; any other index is rejected as ambiguous.
- **Anonymous text adopts a unique ID-only message** (`openai.responseOutputOrder.observeUnindexedEvent`): openai.responseOutputOrder.observeUnindexedEvent associates anonymous text with a previously seen ID-only empty message snapshot only when that association is unique; more than one candidate fails the stream as having no unambiguous identity.
- **Text parts are validated per content index** (`openai.responseTextPart`): openai.responseTextPart tracks each content_index separately and buffers later parts until predecessors finish, because equal concatenated text across snapshots does not prove that every individual part agrees.
- **Added snapshots may only extend a part** (`openai.responseTextPart.prefix`): openai.responseTextPart.prefix accepts an added snapshot that repeats an earlier prefix or extends the current text, but an added snapshot never completes the part and never changes text that already completed.
- **Final message snapshots cannot remove parts** (`openai.responseOutputOrder.messageSnapshot`): openai.responseOutputOrder.messageSnapshot fails the stream when a done snapshot has fewer content parts than already observed, while an added snapshot may still show an earlier prefix with fewer parts.
- **Terminal cannot drop parts with missing predecessors** (`openai.responseOutputOrder.validateTextCompletion`): openai.responseOutputOrder.validateTextCompletion lets a terminal response omit snapshots but fails the stream when any text part has a predecessor that never arrived or completed, so no part is silently dropped.
- **Responses-subset validation is endpoint-scoped** (`openai.validateResponsesItemType`): openai.validateResponsesItemType and the related strict Responses-subset validation apply only to callers of Orka's Responses endpoint (ResponsesInput); other provider consumers keep their existing, more lenient normalization.
- **Validate string wire types despite SDK coercion** (`openai.invalidResponseStringField`): openai.invalidResponseStringField checks that the raw JSON value is a quoted string because the SDK's field validity accepts numbers and booleans coerced into strings; it still allows explicitly empty text and synthetic in-process events with no decoded JSON metadata.
- **Cleared identities cannot be recovered** (`openai.invalidResponseMetadataString`): openai.invalidResponseMetadataString allows a compatible snapshot to omit a required identity (call ID, name, item ID) so it can be recovered from earlier events, but rejects explicitly cleared or mistyped values, which must not restore an earlier identity.
- **Validate bridged call states before merging** (`openai.responseFuncCallTracker.getChecked`): openai.responseFuncCallTracker.getChecked validates every pair of partial call states (by item ID, call ID and output index) before get merges or mutates any of them, because one incoming event may bridge records that were previously separate.
- **Unfinished function items fail immediately** (`openai.responseFuncCallTracker.prepareEvent`): openai.responseFuncCallTracker.prepareEvent rejects an output_item.done function call with a non-completed status before an executable call can be exposed, even if the terminal snapshot later omits that status.
- **Terminal snapshots recover only absent call fields** (`openai.responseFuncCallTracker.prepareEvent`): For response.completed and response.incomplete, openai.responseFuncCallTracker.prepareEvent fills in only function-call fields the terminal omitted (name, call ID, arguments) from earlier events for the same call, then validates the complete output; present fields are never overwritten.

### `internal/operatoraccess`

- **Operator access vocabulary fails closed** (`operatoraccess (file-level)`): Package operatoraccess is the shared vocabulary for `orka task exec`/`orka task cp` across the CLI, orka-api, and the ACP supervisor, and every helper fails closed: an unknown class opt-in value means no access, any taint marker value (even malformed) means tainted, and any path that is not a plain relative path beneath the workspace root is rejected. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Class operator-access opt-in needs a dedicated verb** (`operatoraccess.ClassAccessAnnotation`): operatoraccess.ClassAccessAnnotation is absent by default, and a ValidatingAdmissionPolicy requires the dedicated `operator-access` verb on executionworkspaceclasses to set or change it, so Task authors who can only `use` a class can never enable operator access. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Operator taint marker is durable and controller-protected** (`operatoraccess.TaintAnnotation`): operatoraccess.TaintAnnotation marks both the ExecutionWorkspace and the Task whose RuntimeSession received a write-capable operator operation. The workspace prefix is protected (and made permanent) by the core admission policy and the Task prefix by the provenance webhook; enforcement treats the incarnation as tainted when the workspace or any Task linked to it carries the marker. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Operator access uses dedicated Task subresources** (`operatoraccess.ExecResource`): operatoraccess.ExecResource and FilesResource are virtual `tasks/exec` and `tasks/files` subresources checked with SubjectAccessReview; they are separate from Task create/get and no built-in aggregate role grants them, so ordinary Task permissions never imply operator access. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Operator context-token scopes are explicit** (`operatoraccess.ScopeExec`): operatoraccess.ScopeExec, ScopeFilesRead and ScopeFilesWrite are never implied by Task scopes and are enforced in every context-token authorization mode, including audit mode. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Write-capable operator operations taint first** (`operatoraccess.Operation.Writes`): operatoraccess.Operation.Writes identifies exec and copy-in as write-capable; callers must durably taint the session before such an operation starts, while copy-out never taints. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Taint marker records only safe metadata** (`operatoraccess.Taint`): operatoraccess.Taint is the durable marker value and must carry only safe metadata (time, operation, audit ID, Task UID), never raw commands, file contents, or credentials. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Any taint marker value counts** (`operatoraccess.Tainted`): operatoraccess.Tainted treats any present TaintAnnotation value, including a malformed one, as tainted, so the marker can only be removed by deleting the object, never by corrupting its value. Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Operator paths are rejected rather than cleaned** (`operatoraccess.CleanWorkspacePath`): operatoraccess.CleanWorkspacePath treats a leading `/` as the session workspace root (so `/src/main.go` equals `src/main.go`) and rejects traversal segments, NUL bytes, control characters, invalid UTF-8, and backslashes instead of normalizing them, so an operator path can never escape the workspace.

Recorded in ADR 0044. See [ADR 0044](0044-operator-workspace-access.md).
- **Operator exec stream framing** (`operatoraccess (stream.go, file-level)`): The operator exec WebSocket stream (subprotocol orka.operator-exec.v1) sends only binary messages, each a single channel byte (stdin, stdout, stderr, control, status) followed by the payload; the CLI, orka-api, and the ACP supervisor all depend on this framing.
- **Exec bounds are enforced at API and supervisor** (`operatoraccess.ExecOptions.Normalize`): The operator exec bounds (argument count and bytes, timeout, output and file sizes, frame size, terminal dimensions) are clamped by orka-api and enforced again by the ACP supervisor, so neither side trusts the other's normalization.

- **Codex 429 headers are private to supervisor and auth proxy** (`providerproxy Codex429 headers`): providerproxy.Codex429RouteHeader and Codex429RetryHeader exist only between an authenticated ACP supervisor and the Orka auth proxy; neither the ACP child nor the model gateway may supply or observe them.

- **Publish receipts are idempotent** (`publisher.PublishReceipt`): publisher.PublishReceipt is durable and idempotent for one operation ID and artifact digest, so retries with the same pair return the same receipt.
- **PR presentation is not identity** (`publisher.PullRequestIntent`): publisher.PullRequestIntent carries the immutable PR identity plus controller-authored presentation (title, body, Task name); presentation is deliberately excluded from the ownership key so retries and edits never change which PR is adopted.
- **Session UID scopes PR reuse** (`publisher.PullRequestIntent.SessionUID`): publisher.PullRequestIntent.SessionUID is the immutable owner from the durable Publication; it lets successive publications reuse their own Session's PR without adopting a PR created by another Session that uses the same branch.
- **PR text never comes from workspace output** (`publisher.PullRequestIntent.Title`): publisher.PullRequestIntent.Title and Body come only from trusted Task input, never from agent workspace output.
- **PR receipts bind the exact tuple** (`publisher.PullRequestReceipt`): publisher.PullRequestReceipt must bind to the exact intent tuple; a same-branch pull request with a different tuple is never adopted.
- **PR reconciler contract** (`publisher.PullRequestReconciler`): Implementations of publisher.PullRequestReconciler run inside an SCM-capable clean-room boundary, must look up and reconcile by PullRequestIntent.Key, must not adopt the first same-branch PR, and must not recreate a known closed or merged PR without an explicit higher-level policy decision.
- **Annotated tags are peeled by the service** (`publisher/service.gitRunner (ls-remote resolution)`): Lightweight and annotated tags share the same canonical `refs/tags/...` syntax in publisher validation; peeling annotated tags to commits is the responsibility of the service's Git resolver (ls-remote with `^{}`), not of ref validation.
- **Clean-room rebase fails closed** (`publisher.Publisher.RebaseBranch`, `publisher.RebaseBranchRequest`): publisher.Publisher.RebaseBranch replays the linear chain BaseOID..HeadOID onto BaseOID with git merge-tree --write-tree in an isolated bare repository, with no working tree. Any conflict, merge commit or root commit fails with ErrRebaseRefused or ErrCASRejected before the remote is touched, and a head that already contains the base is left alone.
- **Rebase pushes only with an exact lease** (`publisher.Publisher.RebaseBranch`): RebaseBranch verifies the exact remote head before fetching and pushes with --force-with-lease=<TargetRef>:<HeadOID>, so a branch that moved meanwhile is never overwritten. After a push error it re-reads the remote ref, because the server may have accepted the rewrite before the connection dropped.
- **Rebase size is bounded** (`publisher.maxRebaseCommits`): RebaseBranch lists at most maxRebaseCommits+1 (64+1) commits, so an oversized branch gets ErrRebaseRefused instead of hitting runGit's output buffer cap.
- **Rebased commits keep their author and message** (`publisher.Publisher.RebaseBranch`): Each replayed commit keeps its original author metadata and message, takes the configured committer identity, and optionally gains a DCO Signed-off-by trailer and an SSHSIG signature.
- **Only deterministic signing keys are accepted** (`publisher.ParseSSHSigningKey`): ParseSSHSigningKey accepts only Ed25519 and RSA PKCS#1 v1.5 keys, so independent publishers produce identical commit OIDs and bundle digests for the same prepare request; randomized ECDSA signatures would break deterministic preparation and recovery verification. Passphrase-protected keys are refused fail-closed.
- **Commits are signed as SSHSIG v1** (`publisher.SignGitCommitPayload`): SignGitCommitPayload signs the unsigned commit payload in OpenSSH SSHSIG v1 format with namespace "git" and hash sha512, which is what git verify-commit expects for SSH-signed commits.
- **Signing key rotation is an idempotency conflict** (`publisher tests (SSH signing)`): Retrying a publication with the same Ed25519 key, even from an independent publisher, must produce the identical CommitOID, and changing the signing key under the same PublicationID must fail with ErrIdempotencyConflict.

### `internal/publisher/service`

- **Artifact signing key stays in the controller** (`service.ArtifactAuthorizationRequest`): service.ArtifactAuthorizationRequest binds one artifact transfer to the exact Publisher operation currently executing; in broker mode the raw capability-signing material is never delivered to the Publisher, and service.ArtifactAuthorizationResponse returns only a one-operation capability and its request digest.
- **Artifact signing key stays in the controller** (`service.ArtifactAuthorizationResponse`): service.ArtifactAuthorizationResponse contains only a one-operation capability and its exact request digest and never exposes the artifact signing key to the Publisher.
- **Controller traffic never uses environment proxies** (`publisher/service (in-cluster HTTP clients)`): Every publisher/service HTTP client that talks to the controller or Publisher Service (artifact authorization, artifact client, credential broker, publisher client) uses harnessv2.NewProxylessTransport, because authenticated in-cluster traffic carrying bearer tokens and operation capabilities must never traverse an inherited environment proxy.
- **Transport failures are opaque** (`service.transportError`): service.transportError deliberately does not implement Unwrap, so errors.Is/errors.As (including context.DeadlineExceeded checks) see one opaque failure; only TransportCause exposes the underlying error for callers that classify connection failures.
- **Publisher client has no fixed timeout** (`service.NewClient`): service.NewClient builds an HTTP client without a client-level timeout so operation deadlines come from the caller's context (allowing ORKA_PUBLISHER_PUBLISH_TIMEOUT above three minutes), falling back to defaultRequestTimeout only when the context has no deadline; its transport never resolves environment proxies because every mutation carries the publisher bearer and a signed operation capability.
- **Rollout retry for PR presentation fields** (`service.Client.ReconcilePullRequest`): service.Client.ReconcilePullRequest retries, for up to two minutes, only the exact `invalid_request` JSON rejection a legacy strict Publisher returns for presentation fields, because discovery and mutation can land on different pods during a rollout and that rejection happens before any SCM effect or journal reservation; the same immutable request is resent.
- **Rollout retry for PR presentation fields** (`service.Client.ReconcilePullRequest`): Before each rollout retry, service.Client.ReconcilePullRequest closes idle connections so the next attempt is not pinned to the legacy Service backend that rejected it.
- **Explicit caller deadlines are never clamped** (`service.defaultRequestTimeout`): service.defaultRequestTimeout (3 minutes) applies only to publisher requests whose context carries no deadline; callers with explicit deadlines, such as settlement contexts sized to the publisher's operation timeouts, are never clamped.
- **Bearer and capability secrets must be distinct** (`service.Config (normalize)`): Publisher service configuration rejects a controller bearer token equal to the operation or artifact capability secret: the bearer is transmitted on every request while the capability secrets are signing keys that must never transit, so sharing bytes would let any bearer holder mint valid capabilities.
- **Brokered credentials are never logged** (`service.CredentialMaterialResponse`): service.CredentialMaterialResponse is never logged or persisted by the Publisher; its ResourceVersion is the only retained field and is non-secret audit metadata for the frozen source Secret.
- **Workspace/Publisher service boundary** (`publisher/service (file-level)`): Package service exposes the clean-room Workspace/Publisher boundary: every stateful endpoint requires both the exact controller bearer token and a short-lived HMAC operation capability bound to method, path, canonical request digest, namespace, Task or Publication identity, and operation ID, and the API accepts only credential file references, never raw SCM credentials. Workspace preparation uses a fresh exact-ref bare clone, reads only validated Git blobs, keeps validated relative symlinks but rejects unsafe links, submodules and Git metadata, and uploads a deterministic content-addressed tar through the controller artifact API.
- **HEAD-only transports freeze the OID** (`service (default source ref resolution)`): When resolving a repository's default source ref, some transports advertise only the HEAD object; the service then freezes the exact OID as both ref and revision rather than guessing a branch name, which remains safe because the OID is exact.
- **PAX header overhead sizes the test limit** (`service tests (TestWorkspacePrepareDigestsManifestLargerThanV2WireCaps)`): TestWorkspacePrepareDigestsManifestLargerThanV2WireCaps raises MaxArtifactBytes to 64 MiB because each PAX tar entry costs about 2 KiB of headers, so a 100k-entry tree would otherwise exceed the artifact limit for reasons unrelated to the manifest cap under test.
- **GitHub reconciler tokens are per operation** (`service.GitHubPRReconcilerFactoryConfig`): service.GitHubPRReconcilerFactoryConfig holds only non-secret GitHub REST configuration; each reconciler receives its token from the operation-scoped credential file passed to PRReconcilerFactory.New, and the factory never accepts a token from configuration or environment variables.
- **GitHub reconciler tokens are per operation** (`service.GitHubPRReconcilerFactory`): service.GitHubPRReconcilerFactory creates one short-lived reconciler per operation and never accepts a token in configuration or environment variables.
- **Strict GitHub REST client** (`service.NewGitHubPRReconcilerFactory`): service.NewGitHubPRReconcilerFactory builds a GitHub REST client that denies redirects, applies a hard deadline to every request, and bounds every response body, so a forge or intermediary cannot redirect credentials or exhaust memory.
- **Session marker must be unique** (`service.githubBodyHasReconciliationMarker`): service.githubBodyHasReconciliationMarker treats a PR body that claims more than one Session as ambiguous even when one exact marker is the final line, and a per-head intent marker alone never authorizes Session continuation.
- **Retries do not rewrite PR presentation** (`service.GitHub PR reconciler`): When the GitHub PR reconciler retries and finds the PR it created, it adopts it without rewriting the PR's title or body.
- **Session PR reuse leaves the body untouched** (`service.GitHub PR reconciler`): GitHub moves an open PR's head when its branch is published again; when a Session reuses its PR, the reconciler leaves the original body untouched, including across client retries.
- **Journal reclamation boundaries** (`service.journalStore.reclaimLocked`): service.journalStore.reclaimLocked removes workspace archives only when no started operation can need them for an upload retry, and keeps at most the latest replay record per durable owner-progress boundary, because beginning a later operation proves the controller consumed every earlier terminal result for that Task or Publication; the active operation's record is protected so a delayed replay cannot lose it.
- **Presentation capability is opt-in** (`service.PullRequestPresentationFeature`): Legacy strict v1 Publisher clients reject unknown JSON fields, so the capabilities response must not include the pull-request-presentation feature unless the client opts in.
- **Rollout tests model connection-pinned routing** (`service tests (presentation rollout)`): The presentation rollout tests drain request bodies on the fake legacy backend so its connection stays alive, and model Service routing per TCP connection rather than per request, which is what makes closing idle connections before a retry necessary.
- **Rollout tests model connection-pinned routing** (`service tests (presentation rollout)`): The presentation rollout tests model Kubernetes Service routing per TCP connection rather than per request, so a retry reaches a new backend only after idle connections are closed.
- **Rollout retry for PR presentation fields** (`service.Client.ReconcilePullRequest`): service.Client.ReconcilePullRequest retries a strict-JSON rejection only when the request actually carries presentation fields; a malformed legacy request without them is returned immediately rather than mistaken for the rollout gap.
- **Publisher service never logs sensitive data** (`service.Server.Handler`): service.Server.Handler serves a bounded HTTP API that never logs request bodies, headers, repository URLs, credentials, or upstream error strings.
- **Operation slots require verified capabilities** (`service.Server (operation slot)`): The publisher service acquires its global operation slot only after the operation capability is verified, so an unauthenticated peer cannot hold slots and starve legitimate operations with 429s by drip-feeding request bodies.
- **Publisher service never logs sensitive data** (`service.Server.logOperationFailure`): service.Server.logOperationFailure records only fields already returned to the controller, never request bodies, credentials, repository URLs, or upstream error text.
- **Prepared bundles restore from the controller** (`publisher.Publisher.RestorePrepared`): After complete loss of the Publisher-local prepared cache, Publish and Verify must recover exclusively from the controller artifact API receipt.
- **Workspace archive entry order** (`service (workspace archive ordering)`): The workspace source archive emits parent directories before their descendants, and within each depth and for files the order is deterministic rather than globally lexical.
- **Presentation capability is opt-in** (`service.PullRequestPresentationFeature`): service.PullRequestPresentationFeature is advertised only to clients that opt in, so legacy strict v1 clients never receive an unknown field in their capabilities response.
- **Operation capability scope** (`service.OperationMetadata`): service.OperationMetadata is the durable caller identity bound by the operation capability: workspace preparation is Task-scoped, while publication and PR operations are Publication-scoped.
- **Credentials are passed by reference** (`service.CredentialReference`): service.CredentialReference names a mounted file below the configured credential root; raw credentials are never accepted in API requests, and Role binds brokered requests to one frozen prompt-credential purpose.
- **Local bundle paths stay private** (`service.PreparedPublication`): service.PreparedPublication deliberately omits the Publisher's local BundlePath so callers never depend on or learn Publisher-local filesystem layout.
- **PR credentials are short-lived files** (`service.PRReconcilerFactory`): service.PRReconcilerFactory lets an SCM adapter consume a short-lived, operation-scoped credential file without expanding the public API to raw credentials; the file is deleted immediately after reconciliation.
- **Publisher secrets come from files** (`service.Config`): service.Config contains only already-resolved secrets: the command package loads them from files and clears the corresponding environment variables.
- **Artifact secret is a gated development fallback** (`service.Config.ArtifactCapabilitySecret`): service.Config.ArtifactCapabilitySecret is accepted only when development fallbacks are explicitly enabled; supported deployments use ArtifactAuthorizationBrokerURL so the Publisher cannot mint arbitrary artifact capabilities.
- **Publisher service never logs sensitive data** (`service.Server.logOperationFailure`): service.Config.Logger records each failed operation with only the public error fields returned to the controller; a nil logger discards.
- **Bare source refs stay bare** (`service.CanonicalWorkspaceSourceRef`): service.CanonicalWorkspaceSourceRef validates a workspace source selector but preserves bare names, so the repository-aware resolver can later disambiguate between a branch and a tag of the same name.
- **Manifest digest budget follows configured limits** (`service.workspaceManifestCanonicalLimits`): service.workspaceManifestCanonicalLimits sizes the manifest digest input from the entries it describes (about 1 KiB and 7 items fixed, plus 192 bytes and 5 items per entry, with JSON escaping expanding a byte to at most six) rather than the 2 MiB v2 wire cap, so any tree that passed the configured workspace limits can also be digested.
- **Signing keys stay in memory** (`service.credentialManager.signingKeyCredential`): signingKeyCredential fetches an operation-scoped OpenSSH private key into memory only, never to disk, and returns a cleanup that zeroes the key buffer. The broker transport base64-encodes multi-line PEM keys into one line, while local-file providers return the PEM directly, so both forms are accepted.

### `internal/redact`

- **Redaction matches serialized Authorization headers** (`redact.authorizationPrefix`): redact.SensitiveText recognizes an Authorization or Proxy-Authorization header name bare, as a quoted JSON key, inside a Go http.Header dump, and with backslash-escaped quotes inside an enclosing serialized string.
- **Auth-params stay on their header's line** (`redact.authParam`): Authorization auth-param matching in internal/redact never crosses a line break, so padding cannot swallow the next line's key, while an unclosed quoted value is consumed to end of line so no part of it is left behind.
- **Escaped auth-param values are redacted** (`redact.authParamEscapedValue`): internal/redact also matches auth-param values quoted with backslash-escaped quotes inside a JSON or other escaped string (Token token=\"x\"); an unclosed one runs to end of line.
- **Authorization values are consumed whole** (`redact.authorizationQuotedHeaderRe`): internal/redact consumes the entire Authorization value for any scheme (including GitHub's token scheme, token68, or auth-param lists) because a partial match would drop a parameter name and leave its quoted value unrecognized; quoted header values are matched first since their closing quote can directly follow base64 padding.
- **Redaction errs toward over-redacting** (`redact.sensitiveAssignmentRe`): redact.sensitiveAssignmentRe consumes every non-space character of an unquoted secret assignment so no recoverable credential tail survives behind a comma or semicolon; over-redacting a following word in prose is the accepted, safe direction.
- **Webhook URLs are redacted by path shape** (`redact.webhookURLPathRe`): internal/redact matches Slack, Discord, and Microsoft Teams incoming-webhook URL paths by their shape rather than their host, so proxied or relayed webhook URLs, whose path is the credential, are redacted too.
- **Signed URL signatures need their own rule** (`redact.signedURLQueryRe`): internal/redact has a dedicated rule for signed URL query credentials (Azure SAS sig, AWS SigV4, GCS signatures, generic signature/sas) because those parameter names contain no generic secret keyword the assignment rule would catch.
- **Redaction keeps quoted values quoted** (`redact.SensitiveText`): redact.SensitiveText replaces a quoted secret assignment with a still-quoted placeholder so a later redaction pass cannot consume Markdown delimiters or punctuation outside the original value.

### `internal/taskterminal`

- **No-workspace revision is protocol-only** (`taskterminal.NoWorkspaceRevision`): taskterminal.NoWorkspaceRevision ("empty") is the protocol-only revision harness v2 records for Tasks without a repository workspace; it is not a Git OID. The outbox projector strips it before the schema-validated Task status while immutable payloads keep it, so validation compares delivery evidence through that same normalization, and workspace intent or options alone never establish a repository baseline.
- **Restored projection comparison** (`taskterminal.ValidateRestoredProjection`): taskterminal.ValidateRestoredProjection proves an immutable source terminal projection is compatible with the restored Task incarnation and its final source PromptAttempt, but deliberately does not compare restore-only status text, controller epoch, or transition timestamps, because the restored incarnation records a new settlement event.
- **Legacy Session projection compatibility** (`taskterminal.ValidateFinalizedSessionProjection`): taskterminal.ValidateFinalizedSessionProjection accepts the one legacy Session projection shape that omitted every execution field except the terminal classification, but only when an exact finalized SessionTurn pins that payload digest and the same PromptAttempt.
- **Lease generation differs from RuntimeSession generation** (`taskterminal (session generation fencing)`): In taskterminal validation, a SessionTurn's Key.LeaseGeneration is the per-prompt Session mutation-lease generation and is fenced against the PromptAttempt's recorded lease, while Task.Status.Execution.RuntimeSessionGeneration is the RuntimeSession incarnation generation; they coincide only for a session's first prompt, so turns and attempts bind to the Task through the session UID, never through that generation. Comparing them would make every continuation Task undeletable.
- **Mutation tests re-digest the payload** (`taskterminal tests (projection mutations)`): Projection validation tests recompute the SessionTurn ProjectionDigest after mutating evidence so each case exercises the authoritative evidence check rather than failing early on a payload digest mismatch.
- **Cleanup-only legacy delivery recovery** (`taskterminal.ValidateSessionCleanupProjection`): taskterminal.ValidateSessionCleanupProjection applies the strict finalized-turn contract, except that cleanup alone may recover the delivery classification from the same turn's immutable publication receipt when older recovery pinned an empty NotRequested delivery after the Publication became VerifiedExact. The original payload is never changed or re-enqueued, and the returned classification is not a replacement Task status.
- **Cleanup-only legacy delivery recovery** (`taskterminal.ValidateSessionCleanupProjection`): The NotRequested-delivery compatibility case in taskterminal.ValidateSessionCleanupProjection must not be combined with the omitted-execution-identity or restored-incarnation compatibility paths, because runtime deletion still needs every fence.
- **Cleanup-only legacy delivery recovery** (`taskterminal.ValidateSessionCleanupProjection`): In the legacy NotRequested case, taskterminal.ValidateSessionCleanupProjection takes only the terminal classification from the immutable receipt and validates every remaining payload, attempt, and runtime field exactly.

### `internal/taskwait`

- **Parked approvals are sign-offs only** (`taskwait.ParkedApprovalAction`): A parked approval (taskwait.ParkedApprovalAction) is a sign-off checkpoint delivered to a later turn and never authorizes a gated tool call. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Parked approval payload is unbound** (`taskwait.parkedApprovalPayload`): taskwait.parkedApprovalPayload carries no tool-call binding because the decision is delivered to a later turn that revalidates every policy itself. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Parked approval decisions** (`taskwait.AcceptsApprovalDecision`): taskwait.AcceptsApprovalDecision accepts a human decision for a Task parked on that approval even though the parked turn has ended, but a requested wait arms only when its turn succeeded, so after a failed or cancelled turn it takes no decision. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Minimum continuation budget** (`taskwait.MinContinuationBudget`): taskwait.MinContinuationBudget is the least time a continuation turn must have before the chain deadline; a wait that cannot leave at least this much expires instead of resuming. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Continuations inherit an absolute chain deadline** (`taskwait.ChainDeadline`): taskwait.ChainDeadline returns the absolute deadline a continuation inherited from the first Task of its chain, because a continuation's own timeout is relative to its creation, which happens after the remaining budget was computed. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Chain deadline only shortens** (`taskwait.ClampToChainDeadline`): taskwait.ClampToChainDeadline uses the earlier of a Task's own deadline and its inherited chain deadline, so the chain-deadline annotation can only shorten, never extend, a Task's deadline. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Parking eligibility** (`taskwait.Eligibility`): taskwait.Eligibility allows a Task to park only when a Session records the turn and its inputs can be safely inherited, because the continuation resumes from the Session transcript under the same frozen authority. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Agent-identity Tasks cannot park** (`taskwait.boundToAgentIdentity`): taskwait.boundToAgentIdentity blocks parking for Tasks whose binding froze an Agent identity: the controller, not the requester, creates the continuation, so it cannot re-prove the delegation; a Delegated identity would restart its maximum age at the wake, and a delegated child would lose the parent control its identity requires. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Continuation chain authority** (`taskwait (file-level)`): Package taskwait holds side-effect-free rules for data-only parked turns: a parked Task's turn has ended and its capacity is released, status.wait is the only authority linking it to the continuation Task that resumes its Session, and a chain is settled only when its newest Task is terminal and holds no active wait. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Continuation names derive from UID** (`taskwait.ContinuationTaskName`): taskwait.ContinuationTaskName derives the continuation name from the parked Task's immutable UID so a reused Task name cannot collide with an earlier incarnation's continuation. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Malformed chain index is exhausted** (`taskwait.ChainIndex`): taskwait.ChainIndex treats a malformed or negative continuation index annotation as MaxChainLength, so a corrupted annotation can never extend a chain.
- **Links are proved by controller-written status** (`taskwait.Predecessor`): taskwait.Predecessor and taskwait.Continues verify a continuation link from the predecessor's controller-written status, whose resumed wait must name exactly this Task incarnation; annotations alone never prove a link. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).
- **Links are proved by controller-written status** (`taskwait.Continues`): taskwait.Continues reports a continuation only when the previous Task is the exact incarnation the Task names and its controller-written resumed wait names exactly this Task incarnation. Recorded in ADR 0041. See [ADR 0041](0041-data-only-parked-turns.md).

### `internal/taskwebhook`

- **Resolution failure never permits connect** (`taskwebhook.ErrResolution`): taskwebhook.ErrResolution reports an unresolvable destination, and resolution failure is never treated as permission to connect (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Webhooks reuse the public-address policy** (`taskwebhook.PublicAddressPolicy`): taskwebhook.PublicAddressPolicy reuses tokenexchange.IsPublicAddress after unmapping IPv4-mapped IPv6, rejecting loopback, private, CGNAT, link-local, unique-local, multicast and other special-use ranges (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).

See [ADR 0042](0042-signed-durable-task-webhooks.md).

See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Dial owns its deadline** (`taskwebhook.Dialer.DialContext`): taskwebhook.Dialer.DialContext applies its own deadline covering resolution because net/http detaches dials from request cancellation, and splits the remaining time per candidate so unreachable early addresses cannot exhaust it.
- **Webhook client has no proxy, redirects or reuse** (`taskwebhook.NewHTTPClient`): taskwebhook.NewHTTPClient never uses a proxy (which would dial on the client's behalf and bypass the address policy), never follows redirects, and never reuses connections, so every request re-resolves and rechecks its destination (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Previous key verifies but never signs** (`taskwebhook.SecretKeyPrevious`): taskwebhook.SecretKeyPrevious holds the key retired by the latest rotation; it never signs but stays published so tokens signed before the rotation reached every replica still verify (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Webhooks are never sent unsigned** (`taskwebhook.ErrSigningUnavailable`): taskwebhook.ErrSigningUnavailable means no valid signing key loaded; deliveries fail closed and are never sent unsigned (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Key publication never mints** (`taskwebhook.KeySource.PublishedKeys`): taskwebhook.KeySource.PublishedKeys never writes, so the unauthenticated JWKS endpoint cannot create or mint signing keys; only SigningKeys may mint.
- **Key cache lock is cancellable** (`taskwebhook.SecretKeySource`): taskwebhook.SecretKeySource serializes cache access with a one-slot channel rather than a mutex so a waiter gives up when its context ends instead of queueing behind a stalled load.
- **Mint missing keys, never overwrite invalid ones** (`taskwebhook.SecretKeySource.SigningKeys`): taskwebhook.SecretKeySource.SigningKeys creates a missing Secret and mints a missing current key so fresh installs sign without operator action, but never overwrites an invalid current key; signing fails closed until an operator repairs it (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Key loads are bounded like dials** (`taskwebhook.keyLoadTimeout`): taskwebhook.keyLoadTimeout bounds one signing Secret load, including create or mint writes, at the same 10s as a delivery attempt's connect bound.
- **Stalled Secret reads are bounded** (`taskwebhook.SecretKeySource.load`): taskwebhook.SecretKeySource.load applies keyLoadTimeout even when the caller has no deadline, so a stalled Secret read cannot hold a Task reconcile worker, a JWKS request, or the cache lock indefinitely.
- **Re-read after minting so replicas converge** (`taskwebhook.SecretKeySource.read`): taskwebhook.SecretKeySource.read re-reads the Secret after minting whether or not the update conflicted, because on conflict another replica won and its key is the one every replica must sign with.
- **Key-load test is not parallel** (`taskwebhook.TestSecretKeySourceBoundsStalledLoadsAndCancellableWaits`): TestSecretKeySourceBoundsStalledLoadsAndCancellableWaits must not run in parallel because it overrides the package-level keyLoadTimeout.
- **kid uses RFC 7638 canonical JSON** (`taskwebhook.KeyID`): taskwebhook.KeyID builds the RFC 7638 thumbprint input with required members in lexicographic order and no whitespace; any other serialization changes every published kid.
- **Only the current key signs** (`taskwebhook.KeySet`): taskwebhook.KeySet carries the signing key plus the previous key kept only for verification during rotation; only Current ever signs (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Tokens bind one attempt to its body** (`taskwebhook.Claims`): taskwebhook.Claims binds one attempt of one delivery to the destination audience, the Task, the event type and the exact body digest, so a token cannot be replayed for another receiver or payload (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **Verify is the reference receiver algorithm** (`taskwebhook.Verify`): taskwebhook.Verify is the reference receiver algorithm documented for webhook consumers; changing its checks changes the published receiver contract (ADR 0042). See [ADR 0042](0042-signed-durable-task-webhooks.md).
- **KeyID test uses RFC 8037 vector** (`taskwebhook.TestPrivateKeyPEMRoundTripAndKeyID`): TestPrivateKeyPEMRoundTripAndKeyID uses the RFC 8037 Appendix A.3 thumbprint of the Appendix A.1 key as an external test vector, so the expected value must not be regenerated from the implementation.

### `internal/tokenexchange`

- **Token exchange is policy-agnostic** (`tokenexchange`): Package tokenexchange implements RFC 8693 token exchange and RFC 7523 JWT bearer grants with no knowledge of transaction-token governance or Kubernetes policy objects; callers supply resolved inputs and choose the response validation class (ADR 0011). ## Consequences

- These decisions are still in force. A change that breaks one must supersede that
  entry in a new ADR.
- Symbols get renamed. When an entry's symbol no longer exists, search for the
  behavior it describes.
- Test-mechanics entries (fixture tricks, ordering in tests) are kept so the tests stay
  honest. A later round may supersede them once the tests explain themselves.
