# 69. Decisions recovered from code comments: commands, scripts, and tests

Date: 2026-11-22

## Status

Accepted. This record is a catalog produced by the comment ban in
[ADR 0062](0062-code-carries-no-comments.md). Each entry was a code comment that recorded a
non-obvious decision in `cmd/`, `api/`, `scripts/`, `hack/`, `test/`, `examples/`, and the skill scripts. The comment was deleted, and the decision now lives here.

## Context

Round 2 of the comment cleanup classified every comment left after
[ADR 0063](0063-code-comment-decisions-round-1.md). In `cmd/`, `api/`, `scripts/`, `hack/`, `test/`, `examples/`, and the skill scripts it found 850 distinct decisions
that a reader of the code alone could get wrong. Comments that stated the same rule in several
places are merged into one entry. Where an earlier ADR already records a decision, the entry
links it.

## Decision

Each entry names the symbols it governs, so `rg '<symbol>'` finds the code. Entries are
grouped by package and ordered by source position as of round 2.

### `.agents/skills/kindctl/bin`

- **kindctl cluster discovery fails closed** (`kindctl_kind_clusters`): kindctl_kind_clusters aborts when `kind get clusters` exits nonzero instead of returning an empty list. An empty list on failure (for example Docker unreachable) would make `prune --dead` treat every tracked live cluster as dead and delete its registry entry and kubeconfig.

### `.agents/skills/kindctl/templates`

- **kindctl setup hook environment contract** (`kindctl setup hook (.kind/setup.sh)`): kindctl runs `.kind/setup.sh` after creating the repo-scoped kind cluster with KUBECONFIG already scoped to ~/.kube/kind/<cluster>.kubeconfig, and exports KINDCTL_CLUSTER, KINDCTL_CONTEXT, and KINDCTL_ROOT to the hook. Hooks may rely on exactly these variables and on bare kubectl targeting the new cluster.

### `.agents/skills/orka-kind-deploy/scripts`

- **Kind deploy refuses expired admission TLS** (`deploy_orka_kind.sh validate_admission_tls check`): deploy_orka_kind.sh exits when the existing orka-admission-tls Secret is expired or invalid instead of regenerating it. The test CA and serving certificate last seven days, and an automatic renewal could silently remove shared admission webhooks or bypass other controllers' trust; renewal must be coordinated via config/orka-admission-webhooks/README.md.
- **Registry pushes re-enable errexit inside command substitution** (`deploy_orka_kind.sh orka_kind_registry_push calls`): deploy_orka_kind.sh wraps each orka_kind_registry_push in `$(set -e; ...)` because Bash clears errexit inside command substitutions. Without it a failed tag or push would still yield a reference and the deploy would roll out a stale image.
- **Kind redeploy reuses existing admission TLS** (`deploy_orka_kind.sh orka_e2e_bootstrap_admission_tls`): deploy_orka_kind.sh bootstraps orka-admission-tls only when the Secret is absent. Regenerating it on redeploy would rotate the CA and invalidate the caBundle of already-registered live admission webhooks.
- **Kind deploy always creates vekil-system** (`deploy_orka_kind.sh vekil-system namespace creation`): deploy_orka_kind.sh creates the vekil-system namespace even when no Vekil proxy is installed, because the production overlay applies an ingress NetworkPolicy into that namespace and the apply would otherwise fail.

### `.agents/skills/vekil-reverse-proxy-deploy/scripts`

- **Vekil pods restart when providers ConfigMap changes** (`deploy_vekil_reverse_proxy.sh providers_configmap_changed`): deploy_vekil_reverse_proxy.sh marks providers_configmap_changed and restarts the Deployment whenever the providers ConfigMap is created or configured, because Vekil reads its providers config only at startup and an unchanged pod template would otherwise keep serving the old configuration.

### `api/v1alpha1`

- **Strict-governed runtimes accept only their pinned workspace intent** (`v1alpha1.AgentRuntimeWorkspaceGovernanceStrict`): An AgentRuntime in strict-governed workspace governance mode is eligible only for the exact workspace intent pinned in its immutable runtime profile; a different intent must be rejected rather than widened.
- **Absent AgentRuntime contract version must be rejected** (`v1alpha1.AgentRuntime.RegisteredContractVersion`): AgentRuntime.RegisteredContractVersion returns empty when spec.contractVersion is absent. The CRD defaults the field, so an absent value means the object never passed through the current schema, and callers must reject it rather than assume a contract.
- **Empty Agent tool policy is serialized explicitly** (`v1alpha1.AgentSpec.MarshalJSON`): AgentSpec.MarshalJSON emits an explicitly empty Tools list instead of letting omitempty drop it, because an empty list is a distinct policy from an absent one. Nil and nonempty lists keep the default wire representation.
- **Empty AllowedTools ceiling means deny-all** (`v1alpha1.AgentRuntimeCeiling.MarshalJSON`): AgentRuntimeCeiling.MarshalJSON preserves an explicitly empty AllowedTools list, which permits no tools; omitting it would leave tools unbounded. Serialization must never collapse the empty ceiling into omission.
- **AgentCLIRuntime keeps empty deny-all tool allowlist** (`v1alpha1.AgentCLIRuntime.MarshalJSON`): AgentCLIRuntime.MarshalJSON distinguishes an omitted tool allowlist from an explicitly empty deny-all allowlist; the standard omitempty handling for slices would serialize both as omission and silently widen the policy.
- **Absent Agent built-in contract version must be rejected** (`v1alpha1.Agent.BuiltInContractVersion`): Agent.BuiltInContractVersion returns the explicit built-in harness protocol or empty when spec.runtime.contractVersion is absent; callers must reject an absent contract instead of assuming orka.harness.v2.
- **Agent identity IDs are normalized to lowercase** (`v1alpha1.Agent.IdentityRef`): Agent.IdentityRef lowercases and trims the Entra agent identity ID because identity IDs compare case-insensitively; claims and lookups keyed by the ID depend on this normalization to avoid duplicate or mismatched claims.
- **Agent identity claims outlive their declaration** (`v1alpha1.Agent.HoldsIdentity`): Agent.HoldsIdentity is true when the Agent declares an identity or status still holds an IdentityClaim. The claim persists until the Agent next reconciles, so an identity removed and restored in between remains held throughout and cannot be taken by another Agent.
- **AgentHostTemplate refuses reorder-only updates** (`v1alpha1.TestAgentHostTemplateSpecRefusesReordering`): The AgentHostTemplate CRD must refuse updates that only reorder keyed lists such as init containers and env, because init containers run in order and an env value can refer to an earlier one; keyed-list comparison ignores order, so the immutability rule must compare order explicitly.
- **Connection Ready condition is owned by consent and refresh** (`v1alpha1.ConnectionConditionReady`): The Connection Ready condition reports whether linked token material is held and usable, and only the consent and refresh paths write it; it records the outcome of the last consent and other reconcilers must not overwrite it.
- **Connection scope coverage is a separate controller-owned condition** (`v1alpha1.ConnectionConditionScopesGranted`): ScopesGranted reports whether granted scopes cover the scopes the current mode requires and is owned by the controller, separate from Ready. Widening the mode after consent therefore projects Pending without erasing the still-valid consent, and narrowing it restores readiness.
- **Connections can decline an agent host** (`v1alpha1.ConnectionAnnotationAgentHost`): Setting the orka.ai/agent-host annotation to "declined" on a Connection linked to an agent-host provider keeps the controller from provisioning an AgentHost for that link.
- **ScopesGranted is Unknown while the provider is unresolved** (`v1alpha1.ConnectionReasonProviderUnavailable`): While a Connection's provider is missing, invalid, or unreadable, ScopesGranted is set Unknown with reason ProviderUnavailable rather than False, because scopes cannot be judged against a provider that is not resolved.
- **Connection Ready reason is the durable record of the link** (`v1alpha1.ConnectionReasonLinked`): The Ready condition reason (PendingConsent, Linked, Expired, Revoked), not status.state, is the durable record of a Connection's link, so a transient provider outage that changes state cannot erase the fact that consent completed.
- **Connector CRDs must refuse dropping spec** (`v1alpha1.requireSpecAtRoot`): Transition rules scoped to spec can be bypassed by an update that removes spec entirely, so connector CRD root schemas must refuse dropping spec; requireSpecAtRoot proves this for each CRD.
- **Duration validation accepts typed-client canonical forms** (`v1alpha1 connector timeout CEL validation`): metav1.Duration serializes through time.Duration.String, so typed clients send values like "10m0s" and "500µs"; CRD duration validation rules must accept these canonical forms, not only hand-written ones like "10m".
- **Control-record RBAC markers live with the API types** (`v1alpha1 control-record RBAC markers`): The kubebuilder RBAC markers for the Kubernetes-authoritative ACP control-record store (promptattempts, runtimesessioncontrols, branchclaims, publications, externaleffects, controllerepochs) live in api/v1alpha1/control_record_types.go so RBAC generation does not depend on wiring the store into cmd/main.go.
- **Legacy workspace provider identities remain for frozen snapshots** (`v1alpha1.WorkspaceProviderAgentSandbox`): WorkspaceProviderAgentSandbox ("agent-sandbox") is kept only to interpret execution snapshots frozen before registered workspace controllers; new bindings use registered ExecutionWorkspaceProvider controller names and must not be created with this identity. See [ADR 0049](0049-agent-substrate-v1.md).
- **Substrate provider identity covers MCP tools and legacy snapshots** (`v1alpha1.WorkspaceProviderSubstrate`): WorkspaceProviderSubstrate ("substrate") identifies the retained pooled Substrate MCP Tools and legacy execution snapshots; it is not a registered ExecutionWorkspaceProvider name for new class-backed bindings.
- **maxDelegationAge must decode as a bounded Go duration** (`v1alpha1.OutboundAccessPolicy maxDelegationAge validation`): The OutboundAccessPolicy CRD must refuse maxDelegationAge values that cannot decode as a bounded Go duration, because one such stored object would make the controller's typed list fail and keep it from reading any OutboundAccessPolicy.
- **Remote MCP tool parameters are enforced by consumers** (`v1alpha1.ToolSpec.Parameters (remote MCP)`): Tool spec.parameters stays schemaless and optional in the CRD for compatibility with existing Tools; remote MCP consumers enforce its presence instead, so admission accepts a remote Tool without parameters.
- **Unsupported contract versions fail at JSON decode** (`v1alpha1.AgentRuntimeContractVersion.UnmarshalJSON`): AgentRuntimeContractVersion.UnmarshalJSON rejects any contract other than supported ones during decoding, so neither a client nor the admission decoder can interpret an explicitly requested removed protocol as current work.
- **Runtime JSON decoding rejects removed and case-variant keys** (`v1alpha1.decodeRuntimeJSON`): Runtime CRD objects preserve unknown fields until admission, so decodeRuntimeJSON rejects removed inputs before typed decoding can silently discard them, and only exact schema field names pass because Go's case-insensitive decoding could otherwise turn an unvalidated unknown key into a known field after schema validation.
- **RuntimePool reservation list bound matches capacity limit** (`v1alpha1.MaxRuntimePoolCapacityReservations`): MaxRuntimePoolCapacityReservations (1000) bounds the durable reservation list in RuntimePool status and equals the maximum RuntimePool capacity, so a full pool can always record one reservation per slot; change both together.
- **Tasks fail fast when a pool toolbox cannot bind** (`v1alpha1.RuntimePoolReasonToolboxUnavailable`): When a declared toolbox cannot be bound into the runtime Pod, the RuntimePool reports ToolboxUnavailable and Tasks waiting on the pool fail with the same reason instead of waiting for a rollout that cannot complete.
- **Eviction deadline loss is final and never replays work** (`v1alpha1.RuntimePoolReasonEvictionDeadlineExceeded`): When an evicted execution-workspace runtime fails to drain before the eviction window ends, suspension is never authorized afterward: the instance is lost, its last checkpoint is retained, and uncertain in-flight work is never replayed. See [ADR 0031](0031-native-substrate-checkpoints.md).
- **Task control fields are excluded from soul-bound execution inputs** (`v1alpha1.TaskControlFields`): TaskControlFields lists, by JSON name, the TaskSpec fields (currently suspend) that steer an already bound Task and are not execution inputs, so a soul binding leaves them mutable. TaskControlFields, TaskSpec.ExecutionInputs, and the Task CEL immutability rule must agree; a test checks all three.
- **New TaskSpec fields are frozen by soul bindings by default** (`v1alpha1.TaskSpec.ExecutionInputs`): TaskSpec.ExecutionInputs must clear exactly the fields in TaskControlFields, so any newly added TaskSpec field is frozen by a soul binding unless it is deliberately listed as a control field.
- **Requester permission decisions are limited to agent Tasks** (`v1alpha1.TaskSpec requester permission decisions`): Task admission allows Requester permission decisions only on agent Tasks, because only agent Tasks are planned onto a runtime that can ask before each tool call; AI and container Tasks would run their tools without the requester ever deciding.
- **Providers inherited from a cross-namespace Agent need explicit checks** (`v1alpha1.ProvidersFromAgentInAnotherNamespace`): Provider use authorization checks a Provider an Agent names only in namespaces its admission policies cover, and model fallbacks and a namespace-less providerRef resolve in the Task's namespace. ProvidersFromAgentInAnotherNamespace therefore lists the Agent's providerRef (unless the Task sets its own) and every fallback for an ai Task whose Agent lives in another namespace, so callers can authorize them explicitly; it returns nil for same-namespace Agents and non-Provider Tasks.
- **Capacity waits are retryable and bounded by the Task deadline** (`v1alpha1.TaskExecutionReasonWaitingForCapacity`): WaitingForCapacity is used only when admission is blocked by exhausted RuntimePool or provider capacity; it stays retryable rather than failing the Task, is bounded by the Task deadline, and is mirrored by the WaitingForCapacity condition.
- **Runtime-lost work reports an unknown outcome** (`v1alpha1.TaskExecutionReasonRuntimeLost`): RuntimeLost classifies accepted or running work lost without a provable terminal result, and its outcome must be OutcomeUnknown; it must never be reported as success or failure.
- **Publication that won the CAS survives later cancellation** (`v1alpha1.TaskDeliveryReasonCancellationRequestedAfterPublish`): When publication wins the durable compare-and-swap before cancellation is requested, delivery records CancellationRequestedAfterPublish and must continue reconciling the publication rather than abandoning it.
- **Operator access taints a workspace against publication** (`v1alpha1.TaskDeliveryReasonOperatorTainted`): Operator access to a workspace through `orka task exec` or `orka task cp` taints it, and delivery refuses to publish a tainted workspace with reason OperatorTainted.
- **Only Succeeded, Failed, Cancelled are terminal Task phases** (`v1alpha1.TaskPhase.IsTerminal`): TaskPhase.IsTerminal is true only for Succeeded, Failed, and Cancelled. Scheduled is not terminal because a recurring parent stays Scheduled, and empty or unknown phases are not terminal so callers that gate cleanup or accounting on it fail safe by treating the Task as live.
- **Empty AI Task tool policy is serialized explicitly** (`v1alpha1.AISpec.MarshalJSON`): AISpec.MarshalJSON emits an explicitly empty Tools list instead of letting omitempty drop it, because an empty native tool policy differs from an absent one. Nil and nonempty lists keep the default wire representation.
- **Failed Task webhook deliveries are never retried** (`v1alpha1.TaskWebhookDeliveryFailed`): A Task webhook delivery is Failed when policy rejected it, it exhausted its bounded attempts, it belonged to a parked turn whose continuation now reports instead, or it was an approval notice retired unsent; Failed is terminal and is never retried.
- **Approval webhook notice list reserves an overflow slot** (`v1alpha1.MaxTaskApprovalWebhookNotices`): MaxTaskApprovalWebhookNotices (16) bounds status.approvalWebhooks.notices, and one slot is always reserved for the Overflow notice so receivers learn that later transitions were dropped.
- **Bound Task specs are immutable except control fields** (`v1alpha1.Task execution-authority XValidation rule`): The Task execution-authority CEL rule freezes the whole spec once an ACP agentExecutionBinding exists; for a soul-only binding it compares every field except TaskControlFields, and a test regenerates that field list from TaskSpec so the rule cannot drift.
- **Task tool override keeps empty deny-all list** (`v1alpha1.AgentRuntimeSpec.MarshalJSON`): AgentRuntimeSpec.MarshalJSON distinguishes an omitted task tool override from an explicitly empty deny-all override; collapsing both into omission would silently widen the Task's tool policy.
- **Parked approval waits never authorize gated tool calls** (`v1alpha1.TaskWaitKindApproval`): An Approval wait parks a turn for a human decision on a sign-off the turn requested; resolving it never authorizes a gated tool call, and approvals are never carried across turns. See [ADR 0041](0041-data-only-parked-turns.md).
- **Requested waits arm only after their attempt succeeds** (`v1alpha1.TaskWaitStateRequested`): A wait in state Requested takes effect only after the exact attempt that asked for it settles Succeeded; otherwise it becomes Abandoned, is never armed, and nothing resumes. See [ADR 0041](0041-data-only-parked-turns.md).
- **Continuation Task names are reserved before creation** (`v1alpha1.TaskWaitStateResuming`): The Resuming wait state durably reserves the continuation Task name before the Task is created, so continuation creation is exactly-once across controller restarts.
- **Forwarded writes require approval unless explicitly None** (`v1alpha1.HTTPForwardWrites.WriteApprovalRequired`): HTTPForwardWrites.WriteApprovalRequired treats nil writes or an unset approval as Required; only an explicit None sends forwarded writes without a person's approval.

### `cmd`

- **Snapshot key Secret bootstrap is opt-in** (`main.agentExecutionSnapshotSecretOptions`): When agentExecutionSnapshotSecretOptions.Name is empty the operator supplies the agent execution snapshot key through a mounted file and the controller never writes a Secret; controller-managed key bootstrap applies only when a Secret name is configured.
- **Snapshot key is minted once and loss fails closed** (`main.ensureAgentExecutionSnapshotKey`): The chart never renders snapshot key material, so ensureAgentExecutionSnapshotKey mints 32 random bytes into the empty chart-created Secret on first start and reuses them afterward. If durable dataset history requires a key but the Secret has none, the key was lost and startup fails closed, because minting a new key would orphan every retained snapshot. Concurrent writers race on the Secret's resourceVersion and the loser reuses the winner's key.
- **Audit log sampling test must exceed the sampler budget** (`main agent identity audit log test`): The agent identity audit log test emits 200 entries because the count must exceed the production zap encoder's sampling budget; with fewer entries the test would pass even if audit logs were sampled away.
- **AHP host admits tokens only while owner sign-in holds** (`main.newAHPHost`): newAHPHost builds the AHP host behind --enable-ahp-api with an admit callback that refuses tokens of owners the API would no longer sign in; the API server registers the session backend later, once its handlers exist.
- **AHP requires OIDC sign-in with a subject allowlist** (`main.validateAHPSignIn`): validateAHPSignIn refuses --enable-ahp-api without OIDC issuer and audience and refuses an OIDC configuration without a subject allowlist, because AHP tokens are minted for, and admitted only while, the owner's OIDC sign-in holds, so such an endpoint would be unusable or open.
- **AHP requires Task provenance admission** (`main.validateAHPProvenance`): validateAHPProvenance refuses --enable-ahp-api without Task provenance admission, because who may read an AHP session is decided from the requester recorded on its turns' Tasks, and only provenance admission keeps direct Task writers from forging it.
- **AHP workspace namespace never shares the ACP runtime namespace** (`main.validateAHPWorkspace`): validateAHPWorkspace requires the AHP workspace namespace to differ from the ACP runtime namespace because the workspace namespace gets the restricted Pod Security profile, under which ACP runtime Pods cannot run.
- **Private connector endpoints need a consequence-spelling acknowledgement** (`main.ConnectorPrivateEndpointsAcknowledgement`): --connectors-allow-private-endpoints turns on only with the literal value "i-understand-tokens-may-leave-the-cluster"; the value deliberately states the consequence that a person's linked-account token may be sent to a private address.
- **Private connector endpoints are fixture-only** (`main.connectorPrivateEndpointsPermitted`): connectorPrivateEndpointsPermitted enables the private-endpoint allowance only with the literal acknowledgement and a plain-http localhost connector callback base URL, which only local or CI deployments can have since production callback bases must be public HTTPS origins, so a released configuration cannot enable it by accident.
- **Agent identity issuers require Task provenance admission** (`main.validateAgentIdentityProvenance`): validateAgentIdentityProvenance refuses an Agent identity issuer without Task provenance admission. Identity binding judges a Task by who created it (the RepositoryScan or RepositoryMonitor owner and markers it carries); without the webhook any Task editor could remove them and let an unchecked automation Task bind as a root Task.
- **Class-backed workspaces require Task provenance admission** (`main workspace provider API provenance check`): The workspace provider API refuses to start without Task provenance admission because settlement authorizes controller-privileged revocation and deletion through reserved acp.workspace.orka.ai/ Task metadata, which any direct Kubernetes Task writer could forge without the webhook.
- **Operator workspace access requires Task provenance admission** (`main.validateOperatorAccessSecurityConfig`): validateOperatorAccessSecurityConfig fails operator workspace access closed without Task provenance admission, because the durable operator taint and its workspace link are reserved acp.workspace.orka.ai/ Task metadata that a direct Task writer could otherwise strip to release a tainted workspace for publication or continuation.
- **Removed Substrate v0.1.0 settings are always rejected** (`main.validateSubstrateStartupConfig`): validateSubstrateStartupConfig rejects removed Substrate v0.1.0 settings unconditionally, then validates MCP Tool admission only when it is enabled; recovery with admission disabled is validated separately once existing cleanup obligations are discovered. See [ADR 0049](0049-agent-substrate-v1.md).
- **No OutboundAccessPolicy may mint controller ServiceAccount tokens** (`main controllerServiceAccount reservation`): The controller resolves its own ServiceAccount at startup and reserves it so no OutboundAccessPolicy can mint tokens for it, because the agent identity blueprint trusts that ServiceAccount; startup fails when it cannot be resolved while an identity issuer is configured.
- **Pre-logger startup errors go to stderr** (`main.main early flag errors`): Flag validation errors raised before the controller logger is configured are written to os.Stderr directly, because setupLog would silently drop them at that point.
- **Provenance trust list defaults to configured AI and vendor worker ServiceAccounts** (`main taskProvenanceAdmissionTrustedServiceAccounts`): When --task-provenance-admission-trusted-service-accounts is empty it defaults to the configured AI and vendor worker ServiceAccounts, while explicit overrides are preserved; container worker ServiceAccounts are always excluded from the default.
- **API applies worker rules to every worker ServiceAccount** (`main api.SetWorkerServiceAccountNames`): The API applies admission's worker rules to every worker ServiceAccount, including container workers, regardless of how the provenance trust list is overridden, so overriding the list never exempts a worker identity.
- **Only the controller manager calls the Substrate router** (`main substrateMCPRouter`): The controller manager is the only Orka identity on the Substrate router's SPIFFE allowlist; worker Substrate MCP Tool calls reach Actors through the authenticated orka-api proxy and the ACP broker calls in-process, so workers never get router credentials.
- **OutboundAccessPolicy never mints platform ServiceAccount tokens** (`main outboundaccess.PlatformServiceAccountSet`): The outbound access resolver is given the controller and every worker ServiceAccount as platform accounts so no OutboundAccessPolicy can hand the AI worker a token for them, whether or not they carry labels.
- **Controller servers disable HTTP/2 by default** (`main disableHTTP2`): Unless --enable-http2 is set, the metrics and webhook servers restrict TLS NextProtos to http/1.1 to avoid the HTTP/2 Stream Cancellation and Rapid Reset vulnerabilities (GHSA-qppj-fm5r-hxr3, GHSA-4374-p667-p6c8).
- **Webhook server disables TLS session resumption** (`main webhook TLS SessionTicketsDisabled`): With controller-managed webhook certificate rotation, the webhook server disables TLS session tickets because resumed sessions bypass GetCertificate's current trust check.
- **Manager construction is retried as a startup step** (`main retryStartupStep(NewManager)`): Creating the controller-runtime manager makes the first API server request because the cache resolves per-object settings through discovery, so it runs inside retryStartupStep to survive transient connection errors after a node restart.
- **Agent use enforcement is recorded before serving requests** (`main.establishAgentUseEnforcementPeriod`): The controller records whether Agent use is enforced before anything serves requests, so work created while enforcement was off can never bind an Agent identity, and a new enforcement period starts only once this controller holds leadership.
- **Actor-pool cleanup stays registered when ACP is disabled** (`main SubstrateActorPool cleanup registration`): SubstrateActorPool cleanup controllers remain registered even when ACP execution and Substrate MCP Tools are disabled, so existing actor pools can still release their finalizers.
- **Webhook handlers register before the server is added** (`main registerAdmissionWebhooks`): registerAdmissionWebhooks registers every handler on the local server object before mgr.GetWebhookServer() adds it as a runnable, so the mux is complete before it starts. The server needs its certificate files at start; with controller-managed rotation they appear only after the manager runs, so registration waits for the rotator, otherwise it happens before mgr.Start.
- **ACP GitHub built-ins use only the requester's linked account** (`tools.RegisterBrokeredGitHubTools`): Brokered GitHub built-in tools reach ACP runtimes only through the requester's linked account, so they are registered only when connectors are enabled; without connectors there is no such account and the tools are not offered.
- **Storage adapter Secrets resolve before storage opens** (`main storage Secret resolution`): Secrets referenced by storage adapters are resolved with the direct API reader before any application storage opens and without waiting for the manager cache; a configuration bound only to SQLite reads nothing.
- **Storage adapter bindings are refused, not replaced** (`main storageConfig.RequireEmbeddedSQLite`): Until a storage adapter transport exists, only embedded SQLite can serve a storage contract; a configuration that binds a contract to an adapter is refused at startup and never silently replaced with SQLite.
- **SQLite exclusivity precedes snapshot key minting** (`main.openControllerSQLiteStore`): The controller acquires SQLite exclusivity and validates durable dataset history before deciding whether an absent snapshot key may be created. Application consumers reach storage only through the storage client, which holds the snapshot key; the SQLite store is its in-process provider and a manager runnable.
- **Identity-use audit records pseudonymize requesters** (`main agentIdentityAuditKeyInfo`): The agent identity audit key is derived via HKDF from the snapshot key and pseudonymizes the requester in identity-use records, including records for calls refused while no issuer is configured, so audit logs never carry raw requester identities.
- **Connector OAuth client exists even when consent is disabled** (`main connector OAuth client`): The connector OAuth client is built whether or not new consent is enabled, because the Connection finalizer must still revoke committed tokens for accounts linked before an operator disabled connectors.
- **Connectors require Task provenance admission** (`main --connectors-enabled provenance check`): Connector use trusts spec.requestedBy only when the controller-only provenance annotation proves the API server stamped it, and the controller verifies that sealed stamp before freezing anyone's Connection. Without provenance admission any Task writer could forge both, so --connectors-enabled fails closed at startup.
- **Agent hosts and tools share one Connection credential source** (`main hostCredentials`): Agent-host credentials and connector tools share the same Connection credential source so the two paths never refresh the same OAuth grant twice.
- **Person credentials are resolved only in the controller** (`main connectionSource`): Connection-mode outbound access resolves a person's credential only in the controller through connectionSource; worker Pods keep a nil source and fail closed.
- **AHP workspaces read repositories with the person's own account** (`main ahpBackendConfig.RepositoryCredential`): An AHP workspace reads a person's repositories only with that person's own linked account and only from github.com.
- **Linked-account point reads bypass the cache** (`controller.LiveLinkedAccountsWithCache`): LiveLinkedAccountsWithCache uses the API reader for fresh point reads and the manager cache only for namespace-wide scans such as providers and the authoritative Connection listing.
- **Substrate router is built from identity, not admission flags** (`main runtimePoolSubstrateRouter`): Agent Substrate v1 native workspaces are reached only through atenet-router with the controller's allowlisted pod certificate. The router client is built from the configured identity alone, not the admission flags, because existing routed runtimes still need authenticated recovery, drain, and cleanup after new dispatch is disabled; without the identity routed pools fail closed as Degraded while Pod-backed providers are unaffected. See [ADR 0049](0049-agent-substrate-v1.md).
- **Session deletion keeps authenticated cleanup with admission closed** (`main sessionCleanupDispatcher`): A dedicated session cleanup ACPDispatcher keeps authenticated cleanup available for Session deletion even while new ACP admission is closed.
- **Storage writes are fenced by controller epoch per dataset** (`main controllerEpochManager.WithStorage`): The controller epoch manager advances each storage dataset to the acquired epoch and opens its write fence, and every storage client write waits for the fence of the dataset it targets, so a stale controller cannot write after losing its epoch.
- **ACP runtime image resolution runs after API server and Publisher** (`main.resolveACPRuntimeImagesOrDisable`): ACP runtime image tag resolution needs cluster DNS, which comes up with the node like the API server and the Publisher, so it runs only after both are reachable.
- **Unresolvable ACP images disable agent Tasks only** (`main.resolveACPRuntimeImagesOrDisable`): Failure to resolve ACP runtime images is not fatal because AI and container Tasks do not need them; agent Tasks fail closed until the controller restarts with registry access or digest-pinned runtime images.
- **RuntimePool keeps Substrate trust after admission is disabled** (`main runtimePoolReconciler Substrate configuration`): The RuntimePool reconciler keeps the Substrate provider connection and trust configuration after new admission is disabled so existing Substrate-backed pools can still destroy actors and release their finalizers.
- **ACP dispatcher keeps Substrate routing after admission is disabled** (`main acpDispatcher Substrate routing`): The ACP dispatcher keeps Substrate routing configured after new Substrate admission is disabled, because existing Tasks and RuntimeSessions still need authenticated recovery, cancellation, finalization, drain, and cleanup against their actors.
- **Connector provider reconciler always runs** (`controller.ConnectorProviderReconciler`): ConnectorProviderReconciler runs whether or not new consent is enabled because it owns the finalizer holding a provider while Connections reference it, and a running controller must release that finalizer even after an operator disables connectors.
- **Known built-in tools are looked up at reconcile time** (`controller.ConnectorProviderReconciler.KnownBuiltinTool`): ConnectorProviderReconciler.KnownBuiltinTool consults tools.KnownBuiltInToolNames at reconcile time instead of a startup snapshot, because tools such as the proxy PR tools are registered later in startup.
- **Connection reconciler runs with connectors disabled** (`controller.ConnectionReconciler`): ConnectionReconciler runs even when connectors are disabled because it owns the custody finalizer; Connections created earlier must still finalize (custody deleted, tokens revoked where the OAuth client is available) instead of wedging in Terminating, while new consent stays closed because the API routes are gated.
- **Private-endpoint fixture allowance applies to Tool reconciliation** (`controller Tool reconciler AllowPrivateConnectorEndpoints`): The private connector endpoint fixture allowance is passed to Tool reconciliation too; otherwise fixture Tools would sit at Available=False while the same endpoints are accepted on the provider and at execution.
- **Class-backed settlement is non-destructive without provenance admission** (`controller.TaskReconciler class-backed settlement`): Class-backed workspace settlement performs controller-privileged deletion from reserved Task metadata that is forgeable without the provenance webhook. Cleanup-only installations (the stock installer with bundled CRDs) still start, but the Task reconciler disables the privileged settlement actions and existing workspaces are cleaned through explicit workspace deletion.
- **Patch proposal verification reads the durable control store** (`controller RepositoryMonitor PublicationStore`): Governed publications are recorded by the ACP dispatcher in the Kubernetes durable control store, so verifying patch proposals must read that same store (kubeControlStore), not the SQLite payload store.

### `cmd/build/release`

- **Release bundle manifest rejects unknown fields** (`release bundle manifest`): The release bundle's exact keys are part of the release binding, so decoding rejects additional fields rather than ignoring them.
- **Release candidate assets are immutable while awaiting approval** (`release candidate bundle`): A rerun of release preparation cannot replace images, chart, or CLI assets while earlier evidence for the candidate awaits approval.
- **CLI release targets have a fixed order** (`release.cliTargets`): cliTargets is a fixed ordered list so CLI archive and checksum ordering stays stable regardless of matrix job completion order.
- **Development publication verifies all images before retagging** (`release development publication`): Development image publication checks every uploaded image and immutable sha- tag before changing any tags, so a partial failure never leaves a mixed rolling alias set.
- **Only the newest main build updates rolling aliases** (`release development publication main ref check`): Workflow concurrency serializes development publication, and the main-ref check additionally prevents an older queued run from replacing the newest main build's rolling aliases.
- **Release artifact paths resolve before preparation** (`release main artifact path resolution`): The release command resolves artifact paths to absolute paths before preparation runs, because preparation can change the checkout and relative paths would then point elsewhere.
- **Release runtime images must match this repository** (`release prepare runtime image replacement`): During release preparation an empty runtime image value inherits this repository's image, and a concrete image must match it exactly; the rewrite preserves the field prefix including whitespace.
- **Release tool sources stay within the trusted comparison** (`release prepare trusted paths`): The release command and all its Go sources stay within cmd/build, and the trusted-path comparison lists every path that can affect it; any new repository package the release command imports must be added to that comparison.
- **Only credential-free release commands stream output** (`release prepare build commands`): Release build commands that carry no credentials stream their output for diagnostics; commands that may handle credentials never include arguments or captured output in errors.
- **Release test git fixtures disable background maintenance** (`release prepare test git fixtures`): Release preparation tests disable receive.autogc and maintenance.auto on their git fixtures before any push or fetch, because detached git maintenance can outlive the command and race t.TempDir cleanup.
- **Release tag message format is stable for retries** (`release publish tag message`): Release publication keeps the original tag-message JSON representation so a retried publication can recognize an existing tag as its own.
- **Only missing-manifest responses prove image absence** (`release publish manifest inspection`): Release publication treats only a missing-manifest registry response as proof that an image is absent; authentication, transport, and rate-limit failures stop publication.
- **Version components compare as decimal strings** (`release.compareVersions`): compareVersions compares validated version components (which have no leading zeros) by length and then lexically, avoiding an integer-size limit the version format does not have.
- **Helm repository index bytes are preserved when unchanged** (`release publish Helm index`): Helm refreshes index timestamps each run, so release publication keeps the previous index bytes when entries already match, while still repairing an absent or incomplete index.
- **Release publication dispatches Pages builds explicitly** (`release publish Pages build`): Pushes made with the native GitHub Actions token do not trigger Pages builds, so release publication calls the Pages builds REST endpoint explicitly and waits for it.
- **Release assets are verified even when already uploaded** (`release publish asset verification`): Release publication downloads and verifies every expected asset, including uploads completed by an earlier interrupted attempt.
- **Version updates validate everything before writing** (`release.updateVersion`): updateVersion checks every expected field before writing any file and edits in place, preserving surrounding bytes instead of reserializing YAML so comments and formatting survive.
- **Release checks are never stubbed in tests** (`release.workflow`): The release workflow struct makes only external effects (commands, HTTP, clock) replaceable in tests; release checks themselves always execute.
- **Release command errors never include arguments or output** (`release.workflow.output`): Release workflow commands may handle credentials, so their failures report only the command name, never arguments or captured output.
- **Release JSON decode errors are generic** (`release.workflow JSON decoding`): Release workflow JSON decode failures return a generic error because JSON errors can contain snippets of credential-bearing command responses.
- **Qualification wait leaves time within the runner limit** (`release.workflow qualification wait`): The release workflow waits at most 5h40m for qualification so the parent job keeps time to record evidence within GitHub's six-hour runner limit.
- **Pending qualification runs indicate concurrency contention** (`release.workflow qualification status`): A GitHub Actions run status of pending indicates concurrency-group contention, unlike approval waiting or a queued runner, so the release workflow reports it as queued behind another run.

The CLI reads the current kubeconfig context once; discovery and the bearer token use the kubeconfig as read, and kubectl and the port-forward cache use the context by name, so switching contexts mid-connect cannot pair one cluster's port-forward with another context's credential.

- **kubectl output goes to a file, not a pipe** (`cli.portForwardOutput`): kubectl outlives the CLI and writes a line per connection, so its output goes to a temp file rather than a pipe that would break when the CLI exits; the file is unlinked at once where possible, while Windows removes it only after kubectl stops.

- **Fresh sign-in supersedes GitHubMembershipEnded** (`cli.agentHostReasonGitHubMembershipEnded`): After a successful sign-in, a kept host's GitHubMembershipEnded failure is stale because the account is a member again; the CLI waits through it since the host recovers at its next reconcile.

- **Agent host wait ignores hosts from other links** (`cli.waitForAgentHost`): Until the new link's agent host exists the API can return a host kept from another link or one being deleted; waitForAgentHost ignores those and waits for the host fed by the new connection.
- **Operator suspension is checked before readiness** (`cli.waitForAgentHost`): waitForAgentHost checks OperatorSuspended before Ready because a just-suspended host can still report Ready from its last run, and an operator's suspension is theirs to lift; an idled-out host is woken once instead.
- **Agent host wait tolerates failures the new link clears** (`cli.waitForAgentHost`): A host kept from an earlier link keeps showing that link's failure until the controller sees the new one, so waitForAgentHost waits through Failed reasons the new link can clear and reports them only if the wait ends on one.

- **Invite requests send no namespace** (`cli.controllerWide`): Invite requests send no namespace because invites act in the namespace the controller watches, which the CLI's default namespace would contradict and the server would refuse.
- **Tokens with orka_s_ are sessions wherever they come from** (`cli.sessionTokenPrefix`): Every Orka session token starts with orka_s_, so a token passed with --token that has this prefix gets the same session protections as a saved one.
- **Credential-carrying clients never follow redirects** (`cli.noRedirectClient`, `cli.sessionAPIClient`): noRedirectClient and sessionAPIClient answer redirects as-is instead of following them, because a redirect from the server or a proxy would send credentials past the origin and transport checks.

- **Session renewals take turns under the config lock** (`cli.configuredSession`): The server renews a session only once, so configuredSession renews under the config lock; a process that finds a successor of the same person's session already saved uses it, and never renews or uses another person's session saved meanwhile.

- **Tracker learns child Task names from creation results** (`cli.tracker.recordCreatedTaskName`): cli.tracker.recordCreatedTaskName stores the task name reported by a delegate_task or create_agent_task result, because delegate_task always generates the child name; later progress and wait results can only be matched to the tracked agent by that returned name.

- **Wait results complete only agents reported terminal** (`cli.tracker.completeAgents`): cli.tracker.completeAgents applies the phases a wait tool reports: agents not reported terminal stay pending so a later cancellation is still recorded, and a failed tool call completes nothing. - **Cancelled Tasks are terminal failures in the tracker** (`cli.tracker.applyTaskPhaseLocked`): cli.tracker.applyTaskPhaseLocked marks a Cancelled task done and unsuccessful; leaving it pending would let stop or completeAgents later mark it as a success.

### `cmd/orka-host-agent`

- **Host idle status goes stale after ten minutes** (`staleAfter`): staleAfter is ten minutes because hosts rewrite idle status at least every five minutes; twice that absorbs write and clock jitter so a host that keeps to the contract never flaps.
- **startupz never authenticates** (`agent.startupz`): agent.startupz completes one AHP handshake without authenticating, so it never claims a single-user host, and then stops talking AHP so it cannot keep the host from being idle. See [ADR 0035](0035-agent-hosts.md).
- **Readiness probes complete the startup handshake after a restart** (`agent.ensureStarted`): agent.ensureStarted runs from readiness and liveness probes too, because a restarted sidecar starts over after the host's startup probe has already passed for good.
- **readyz prefers fresh idle status over listener checks** (`agent.readyz`): agent.readyz treats a host with fresh idle status as alive without touching its listener, because hosts may log every connection that never completes a handshake; otherwise it only checks the loopback listener accepts connections and never opens an AHP session.
- **Idle status endpoint forwards only fields Orka reads** (`agent.status`): agent.status serves the host's idle status limited to the fields Orka reads rather than passing the host file through.
- **Agent, not host, judges idle-status staleness** (`agent.readStatus`): agent.readStatus judges staleness from updatedAt, or the file modification time when absent, rather than trusting the host; a time further in the future than staleAfter is as untrustworthy as an old one.
- **Future idleSince marks status stale** (`agent.readStatus`): agent.readStatus marks status stale when idleSince is more than staleAfter ahead, since idle time would count from the future and the host would not suspend until then.
- **ahpHandshake never authenticates** (`ahpHandshake`): ahpHandshake offers every AHP protocol version the Go client supports and pings, but never sends authenticate, so probes never claim a single-user host.
- **Host containers run orka-host-agent init as PID 1** (`runInit`): runInit is the host container's init process because a container entrypoint is PID 1 and adopts every orphan, and agent daemons do not reap children they never started, so orphans such as git's detached maintenance would stay zombies; runInit forwards signals, reaps everything, and returns the command's exit code or 128 plus the killing signal.
- **Subscribe to signals before starting the command** (`runInit`): runInit calls signal.Notify before starting the command so no signal is lost between start and subscription.
- **Forwarded-signal errors are ignored** (`runInit`): runInit ignores errors when forwarding a signal because the command may already be exiting, and reap reports that exit next.
- **Host agent stages token and binary for the host** (`stage`): stage runs as an init container under the host's uid and copies the connection token into a memory-backed volume only the host mounts and itself into a read-only volume, so host images need no tools to run orka-host-agent init.
- **Staged token is replaced, not overwritten** (`stage`): stage replaces an unconsumed token via replaceFile because the earlier token file is read-only (0440) and cannot be rewritten in place.

- **Preflight fails explicitly when called in a conditional** (`scripts/tests/agent-substrate-e2e-hardening-test.sh`): Calling a Bash function in a conditional disables errexit inside it, so substrate_prepare_upstream must return failure explicitly before creating or installing anything rather than relying on set -e.

### `test/e2e`

- **Fake Entra tokens live 70s to exercise re-verification** (`e2e.fakeEntraTokenLifetime`): The controller caches an Entra token until one minute before it expires, so e2e.fakeEntraTokenLifetime is 70s: each token is reused for only about 10s and a disabled identity is noticed on the next request. Lengthening it makes the disabled-identity spec wait or pass on a stale token.
- **Agent-use policy must be installed with the authorization flag** (`e2e.Describe(Agent identity with a fake Entra)`): --agent-use-authorization-enabled trusts that config/agent-use-policy is installed; only with that policy are direct Task writes also checked for `use`. The agent identity e2e spec therefore applies the kustomization before running Tasks and removes it afterwards.
- **Identity binding requires a Task created after the grant second** (`e2e.Describe(Agent identity with a fake Entra)`): Only a Task created in a later second than the identity grant may bind the identity, and both timestamps have one-second precision, so the agent identity e2e spec sleeps until two seconds after the grant before creating Tasks. Removing the wait makes binding flaky.
- **Agent re-verification is triggered by a generation change** (`e2e.Describe(Agent identity with a fake Entra)`): The controller keeps its last Agent identity verification until the Agent's generation changes, so the disabled-identity e2e step waits for the cached token to lapse and then patches spec.runtime.defaultMaxTurns rather than an annotation. - **A disabled identity is refused before any resource token request** (`e2e.Describe(Agent identity with a fake Entra)`): After the issuer refuses an Agent identity, Orka refuses the Tool call itself and never requests a token for the resource; the refusal reaches the model as a failed tool call. The e2e spec therefore accepts either terminal Task phase and asserts the call was attempted, refused, and that resourceTokenRequests did not grow.
- **Fake Entra e2e enables the fixture-only private-endpoint allowance** (`e2e.configureControllerForFakeEntra`): e2e.configureControllerForFakeEntra turns on the fixture-only private-endpoint allowance so the identity-backed Tool can reach the in-cluster fake resource; that allowance requires a plain-http localhost callback base, which the spec never uses. A field checked but not fingerprinted could change between reads unnoticed.
- **RuntimeSession home stays child-owned under read intent** (`e2e.runtimeSessionProcessesScript`): e2e.runtimeSessionProcessesScript reads the owner of the RuntimeSession's private home rather than the session root, because a read-intent workspace protects the session root and workspace while the home stays owned by the session's child UID.
- **Adapters are found as PID 1 children leading their own group as the session UID** (`e2e.runtimeSessionAdapters`): The ACP supervisor (PID 1 in the runtime container) starts each adapter as the leader of its own process group under the session's private UID, which also owns the session's private home. e2e.runtimeSessionAdapters and parseRuntimeSessionAdapters identify a RuntimeSession's adapters by exactly those three properties.

## Consequences

- These decisions are still in force. A change that breaks one must supersede that
  entry in a new ADR.
- Entries were recovered from comments in bulk, and a few original comments were stale or
  overstated. If an entry disagrees with the code, treat that as a bug in the entry: confirm the
  intended behavior, then fix the code or supersede the entry in a new ADR.
- Symbols get renamed. When an entry's symbol no longer exists, search for the behavior it
  describes.
- Entries recovered from test comments record why a test is shaped the way it is, so the test
  stays honest. A later ADR may supersede them once the tests explain themselves.
