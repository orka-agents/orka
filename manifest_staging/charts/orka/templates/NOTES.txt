For operators:

  CRD lifecycle:
    - A fresh install creates Orka's cluster-scoped CRDs unless --skip-crds is used.
    - Helm does not update CRDs during helm upgrade. Apply the CRDs from the exact
      target chart before upgrading the release.
    - helm uninstall retains the CRDs and all Orka custom resources.

  Upgrade guidance: helm show readme <the same chart reference or archive>

  Generic Gateway CRD upgrade:
    Helm installs CRDs on first install but does not upgrade them automatically.
    If CRDs are managed separately, pass --skip-crds to helm install/upgrade.
    Before enabling gateways on an existing release, apply the CRDs from the published chart version, then upgrade again:

      helm repo add orka https://orka-agents.github.io/orka/charts
      helm repo update orka
      helm show readme orka/orka --version {{ .Chart.Version }}

    Follow the README's guarded exact-spec replacement procedure (or the matching
    source checkout's scripts/apply-helm-crds.sh) before upgrading. The controller
    remains gateway-disabled until all three Gateway CRDs and the Task
    session-cutoff schema are observed.
